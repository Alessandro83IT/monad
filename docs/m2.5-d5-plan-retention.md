# M2.5-D5 — plan references, GC and generation discard

Baseline: `main`, `cef826e`. D5 is internal retention machinery, not execution,
selection commitment, migration, pin retirement or cleanup authorization.

## Contract

The generation-side D2 projection binding discovers exactly one projection/store
pair. Only an absent binding leaf in an existing safely opened generation
authority means no registered projection. Inspection errors, unsafe/malformed
bindings, a missing projection-side counterpart or mismatched authorities fail
closed. D2 initialization and D4 mutations hold exclusive State: before the
generation witness exists, a one-sided initial binding cannot authorize D4 plans.
Deletion of established binding records by equivalent-authority external writers
is excluded by the inherited trusted-namespace contract; D5 cannot discover an
arbitrary orphan projection after its sole locator witness has been erased.

| State | Retention decision |
| --- | --- |
| No projection binding, or valid binding without D4 infrastructure | Empty plan references; existing C roots still apply |
| Valid published canonical intent/plan pair | Retain target, selected base and every declared source |
| Complete private canonical pair with exact ID/binding | Same roots as published; visibility/durability/execution are not inferred |
| Incomplete private pair, wrong bytes/schema/ID/binding, extra entries | Abort destructive operation; preserve all evidence |
| Bootstrap residue, including a structurally complete private bootstrap | Abort destructive operation pending explicit D9 disposition |
| Duplicate activation ID across private/public locations, unsafe metadata/mount, scan/read failure | Abort, never substitute empty roots |
| Unrelated malformed published pair | Abort retention scan, although D2/D4 structural validation may legitimately leave its bytes opaque |

Both old and new sources are retained, including unused declared sources.
ArtifactSource retains its ArtifactId. LegacyTreeSource retains its contained
store locator; LegacyAliasSource retains both the locator and explicit ArtifactId.
For a nested legacy locator, retain its top-level store ancestor because current
legacy GC detaches top-level entries. Locators outside the bound store reject.
Roots may name absent objects/generations: absence does not authorize dropping a
reference. Generation document digests, source seals and alias targets remain
claims for D6/D7; D5 does not authorize execution or require source availability.
Repeated references across different plans are unioned. Duplicate sources inside
one plan retain D1's rejection rules.

## Lock and durability invariant

The scanner requires the caller's namespace-derived held State lock (shared is
sufficient for observation). It acquires no locks. GC holds State then StoreGc,
validates all C and D5 roots before selecting candidates, and rescans under the
same locks before each detach, retaining both locks through both detach barriers.
Discard holds exclusive State from scan through deletion and rejects a referenced
generation. D4 writers cannot publish or prepare across those intervals. External
writers with equivalent authority must remain quiescent as in D2–D4.

Protection concerns authoritative objects and generation metadata. A root declared
after an already completed C detach does not resurrect that private trash inode;
explicit C trash reclamation retains its existing contract. A future command that
requires an available source must acquire its lifetime from an existing generation
under State or from C pins before releasing that protection. D4's ability to
persist claims about absent sources is not a source-acquisition API. D6–D8 must
reject unavailable execution sources rather than treating D5 retention as proof
of their availability. No inverse rename or rollback of durable C detach is added.

An error in the initial snapshot prevents the first detach. An error in a later
per-detach snapshot stops the remaining pass; earlier durable, unrelated detaches
are not rolled back. No partial snapshot escapes the scanner on an exception.

D5 performs no writes, fsync, rename or cleanup. Inspection uses the D2 no-follow,
owner/mode/link/mount gates and D4 bounded pair reader, canonical codecs and
binding checks. Before returning, it rechecks pair bytes/instances and namespace
observations. It does not replace B/C durability barriers or claim that inspection
establishes plan durability. A scan error is read-only; C errors after a detach
retain their existing uncertainty semantics.

## Resource bounds

D4's combined 4,096 container bound and independent 16 MiB document bounds remain
unchanged. D5 additionally bounds one scan to 64 MiB of combined document bytes
and 262,144 declared reference occurrences (target, optional base and sources).
Exceeding a retention budget blocks reclamation; it does not invalidate or delete
a D4 plan. One pair is decoded at a time, descriptors do not scale with container
count, and reference sets deduplicate across pairs. This may conservatively block
large valid namespaces until an explicit later retention policy is available.

## D9 boundary

No automatic expiration, status consumption, recursive plan deletion, bootstrap
repair, incomplete-preparation completion or pin retirement is permitted. Complete
and aborted status codecs confer no D5 deletion authority. D9 must define terminal
record publication, eligible retention and cleanup before any reference is removed.

## Internal APIs and integration

`activation/plan_retention.hpp` introduces `PlanReferences` (generation ID,
ArtifactId and top-level legacy locator sets plus public/private counts) and
`scan_plan_references(generations, held_state, optional_expected_store, io)`.
The optional store expectation is mandatory at the GC call site. Discard discovers
the store through the exact D2 binding and never infers it from a state parent.
The scanner verifies ownership of the supplied namespace-derived State lock;
its caller remains responsible for the correct lock classification/mode and
exclusion interval. Returned sets are values, not reusable lifetime capabilities.

`PlanAccess::retention(context)` reuses D4's constrained bounded pair readers,
canonical codecs, authority checks, administrative enumeration and error outcomes.
It decodes every public/private pair, accumulates conservative references, and
reopens each pair against original inode/metadata/digest observations before
conclusion. It keeps value observations across pairs rather than retaining a
descriptor for every container. Discovery separately pins and checks the D2
generation-side binding through conclusion. The inherited State/external-writer
exclusion contract remains normative; controlled persistent substitutions are
tested, not universal detection of arbitrary post-observation hostile mutations.

The new scanner propagates D1/D2/D4 and filesystem errors; it does not turn any
exception into an empty root set. D5 failures have no content/namespace mutations.
Existing GC/trash persistence errors keep their existing C outcome semantics.

GC's initial snapshot and each per-detach snapshot now union D5 source sets with
all-generation and transaction-pin roots. Discard checks D5 generation IDs before
its existing current-generation guard and deletion, under exclusive State.
No D1 bytes, current codec integration, source sealing, D4 publication barriers,
transaction retirement, trash walker or live activation protocol is changed.

## Nonprivileged execution record — 2026-10-13

Baseline `cef826e` plus the uncommitted D5 changes. Fresh CMake builds in
`/tmp/athena-d5-debug` and `/tmp/athena-d5-release` both succeeded. Final complete
selected suites: **90 PASS, 0 FAIL, 0 SKIP per configuration**, including existing
B/C/D1–D4, locking, durable-filesystem, generation, install/remove and packaging
regressions. The selection deliberately excludes privileged and scanner-backed
integration cases; these exclusions are not claimed as executed CTest SKIPs.
The final inventory is 112 cases, of which 22 are excluded by this selection.

```sh
cmake -S . -B /tmp/athena-d5-debug -DCMAKE_BUILD_TYPE=Debug
cmake --build /tmp/athena-d5-debug --parallel 4
cmake -S . -B /tmp/athena-d5-release -DCMAKE_BUILD_TYPE=Release
cmake --build /tmp/athena-d5-release --parallel 4
ctest --test-dir /tmp/athena-d5-debug -LE privileged \
  -E '(scanner|integration|immutable_object_publication|generation_activation)' \
  --output-on-failure -j4
ctest --test-dir /tmp/athena-d5-release -LE privileged \
  -E '(scanner|integration|immutable_object_publication|generation_activation)' \
  --output-on-failure -j4
```

Final Debug suite elapsed 80.91 s; Release 41.42 s. Execution logs are retained
locally at each build directory's `nonprivileged-validation.log`. An intermediate
test refinement failed because its State-busy probe caught PersistenceError
instead of the foundation's actual system_error; the test was corrected to
require EAGAIN/EWOULDBLOCK. Final D5-only and full suites pass after that correction.
Release reports the existing ignored-write-return warning in
`tests/core_foundation_test.cpp:135`. `git diff --check` passes. No commit or push
was performed.

`/tmp` is tmpfs. These results establish tested ordering, error handling and
process-death mechanics, not reboot/power-loss durability or completion of M2.5.

| `activation_plan_retention_privileged_nested_test` | Nested tmpfs mount over a plan container, differing device/mount ID | PASS | PASS |
| `activation_plan_retention_privileged_ext4_test` | Publication, retention scan, discard rejection and actual GC on an existing ext4 fixture parent | PASS | PASS |

Total across both configurations: **8 PASS, 0 FAIL, 0 SKIP**. The cases are
labelled `privileged`, with explicit skip code 77 and independent outcomes.
Mount cases require effective
root and CAP_SYS_ADMIN; ext4 requires `ATHENA_D5_EXT4_TMPDIR` naming an existing
dedicated root-owned directory. The ext4 case checks both filesystem magic and
mountinfo. Tests never format a device. Mount cleanup failure fails qualification
and preserves the fixture instead of recursively deleting through a mount.

The qualification procedure uses a root shell on the **Debian qualification VM
only**, with a dedicated directory on an already existing ext4 filesystem:

```sh
umask 0077
install -d -o root -g root -m 0700 /var/tmp/athena-d5-ext4
export ATHENA_D5_EXT4_TMPDIR=/var/tmp/athena-d5-ext4
ctest --test-dir /tmp/athena-d5-debug \
  -R '^activation_plan_retention_privileged_.*_test$' --verbose
ctest --test-dir /tmp/athena-d5-release \
  -R '^activation_plan_retention_privileged_.*_test$' --verbose
```

Post-run checks found no residual mounts with `findmnt` for `athena-d4`,
`athena-d5` or `athena-t17`, and no residual fixtures in
`/var/tmp/athena-d5-ext4`. The repository was clean after qualification.

Existing B/C scanner suites, D3 scanner and D4 T17 must also be requalified

# M2.5-D8-B1.2/B1.3 — prepared operational request boundary

## Scope and prerequisite

B1.1 is consolidated at `b10405756b4afad5d7ead7c6ac196c767bb9b41d`.
All 391 committed source hashes match final TOML qualification run `-3`.
This layer is internal; it adds no installed public header or CLI dispatch.
The TOML frontend, codecs, D4/D5/D6/D7, D8-A and D8.2 are unchanged.

## API and responsibility

`src/activation/operational_request_runtime.hpp` defines:

- `prepare_operational_request(context, held_state, input, expected_digest)`:
  recursively copy, validate and normalize through B1.1/D8.1, then reobserve
  the persisted documents and current record. Return the detached B1.1 value.
- `revalidate_operational_request(context, held_state, prepared, expected_digest)`:
  return `OperationalRequestState::BaseCurrent` or `TargetSelected`. This is a
  transient identity observation, never a capability or durability certificate.
- `activate_prepared_operational(context, held_state, prepared)`:
  forward the frozen input and pinned plan digest to the unchanged D8.2
  coordinator. No alternate publication/selection/reconciliation path exists.

The caller supplies ActivationId, binding, explicit base, exact base/target
generation documents, complete source inventories and predecessor witnesses.
Inputs must be snapshots of caller-verified source observations as required by
D8.1/D8.2. This layer does not discover a base from a symlink, select a target,
generate an ID, scan/seal sources, bootstrap, migrate, acquire ownership or
construct missing evidence. Structural verification cross-checks membership,
source identities, paths, owner references, generation digest and plan digest.
Serialized claims, including apparently plausible seals and witness IDs, remain
claims after successful decoding, preparation and identity revalidation.

## Exact identity and revalidation

Preparation delegates to the B1.1 factory before filesystem observation, so
normalization cannot mutate caller containers or preserve mutable element aliases.
Exact document bytes survive comments, CRLF and historical accepted schemas.
PlanIdentity is derived by D8.1 and independently supplied expected digests are
checked without replacing it. No input/base/identity/digest field is rebased.

Revalidation requires the same ProjectionBinding and State authority. Existing
`inspect_selection` validates the constrained context/State and current record.
The observed current must equal the original base, unless it is an exact target
retry with the same activation ID, generation and plan digest. Both persisted
generation documents must match their original digest AND exact bytes, including
the original base document on retry. A second current/context observation rejects
a change across document reads. Missing, malformed, oversized, symlinked or
substituted generation documents fail through the existing bounded no-follow
reader. Neither observation repairs barriers or promotes a preparation.

Revalidation intentionally does not claim that a source exists/is durable, that
a witness proves ownership, or that an earlier selection/reconciliation completed.
Only D6/D7 can establish those facts through their existing fresh authorization.
In particular a fabricated source can pass structural/document observation and
still be refused by D6. A successful observation is not reusable execution
authority; the execution wrapper never accepts such an observation as input.

## Locks, lifetime, retry and errors

All three APIs require caller-held exclusive ProjectionState, ordered after any
TransactionLease and before StoreGc. No State or StoreGc is acquired by the new
layer. Generation lifetime protection lasts until D4 publishes its references;
D5 retention and transaction pins remain the caller/existing primitive contract.
Managers, TransactionPins construction/handoff and cleanup are not called here.
Equivalent-authority writers and mount changes must be excluded by the caller,
as in D8.2; a second observation cannot solve ABA or arbitrary external mutation.
Calling with concurrently mutated C++ input is outside the language contract.

Preparation/revalidation perform no publication, fsync, recovery or cleanup.
They preserve existing SchemaError, ExecutionError and generation read exception
types. ExecutionError's NotMutated here describes this observation only; it says
nothing about an earlier attempt's selection or durability. On execution, the
unchanged D8.2 OperationalActivationError preserves stage, underlying exception,
canonical identity and BeforeSelection/SelectionUncertain/AfterSelection. No
revalidation success changes those categories. Exact retries still execute D6
barrier recovery and D7, preserving uncertain plans, witnesses and generations.

## Qualification and limits

The dedicated nonprivileged runtime test covers exact historical documents,
snapshot detachment, codec roundtrip, explicit digest mismatch, structural
membership/witness errors, wrong binding/State, target and base document changes,
malformed/missing/symlinked/oversized files, same-identity retry, competing prepared
requests across State intervals, concurrent immutable codec consumers, failed
inspection, retry digest conflict and a changing-current fault. Mutation and
fsync callbacks assert that preparation/revalidation are read-only. D6 rejection
of fabricated source claims and pre/post-current-rename/D7 faults exercise the
prepared wrapper with exact same-request recovery and retained residues.

Full Debug/Release qualification uses `tests/qualify_bounded_toml.py` with fresh
build/output paths. Its explicit input inventory includes this document, the new
runtime files/test, the existing frontend and every declared build/test input;
it rejects unlisted additions and verifies source hashes after both suites.
The new runtime binary is included in binary hashes. Results/evidence are recorded
separately after execution; previous qualification directories are retained.

Existing B1.1/H1/H2/H3, upstream differential/coexistence, D8.1/D8.2, selection,
reconciliation, locking and recovery tests remain required. Privileged scanner,
physical nonempty witness/mount/migration, OOM stress and power-loss tests are not
run on the MSI. Tests establish finite observations under the supported local
filesystem/toolchain, not universal ODR, RSS, arbitrary race or power-loss safety.
The competing-request test models serialized writers; the concurrent test covers
immutable codec consumers, not simultaneous mutation of a shared context.
The closure audit additionally checks physical D2 hard-linked symlink witnesses
and rejects a same-target different-inode replacement. It demonstrates that the
identity-only B1 observation does not certify even a real witness; D6 separately
rejects an empty-base request against the now nonempty projection. This is not
a nonempty, source-authorized B1 transition or privileged scanner qualification.
The fabricated-source case uses historical provenance and checks actual source
inode observation, LegacyError/ProjectionError causes and ENOENT, so an earlier
modern-metadata failure cannot satisfy the regression. Selected-target retry also
checks that corruption of the original base document cannot be ignored.
No CLI integration, source discovery, recovery policy, B2 or operational selection
policy is designed or implemented by this layer.

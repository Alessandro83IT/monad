# M2.5-D8-B1 — commit readiness after removing the CLI-document dependency

## Cause and bounded correction

The previous NO-GO was a documentary dependency, not a parser or operational
security requirement. The old driver appended the historical CLI report to
`paths` (old line 50) and hashed it unconditionally through `sha()`/`read_bytes()`.
The report was not parsed or used by any build, codec, budget, ownership, lock,
recovery, selection, digest or authorization assertion. Its presence was merely
recorded as context, yet omission from the commit made reproduction fail.

The driver now uses `tests/bounded_toml_sources.txt`, an explicit sorted input
inventory including itself, the inventory, every build/test dependency in the
existing source roots and the frontend architecture document. Historical CLI
context is outside that documented scope. This is not an optional-read fallback:
missing inputs fail, and new unlisted source files, removed files, symlinks and
changed contents fail. Source roots and the pre-existing generated `__pycache__`
omission are recorded in environment.json. End-of-run verification checks the
file set again as well as all contents. Complete CTest logs are retained directly
by the driver, beyond JUnit output truncation.

Seven regression checks use copies of the real declared inputs. They prove that
the declared tree qualifies without any CLI document, and reject missing,
modified, removed, unlisted, symlinked and out-of-scope required inputs. No
placeholder or duplicate CLI document was created. No parser, codec or
operational production source was changed in this correction.

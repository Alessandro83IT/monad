# M2.5-D3: legacy sealing and explicit adoption

These are internal primitives, not migration orchestration. Neither API writes
`generations/current`, activates a generation, replaces a managed link, changes
payload permissions, or deletes legacy content. M2.5-F must decide when to call
them. D4 plan persistence, D5 GC/discard integration, D6 selection commit, D7
reconciliation, D8 command integration, D9 retention/cleanup, and D10 power-loss
qualification remain outside this change.

## Audited compatibility formats

The old store installer copies regular files from staged `usr/` into a
name/version directory. It can dereference staged file symlinks and omits empty
directories. Its ownership list is `.athena/manifest.toml`, containing
`[[files]]` tables with one string `path` each. Directories are scaffolding,
not manifest entries. The metadata writer emits `.athena/metadata.toml` with
`name`, `version`, `source`, `sha256`, `build_system`, optional string-array
`dependencies`, and optional `provides.capabilities`/`provides.features` arrays.
Those bytes are administrative source metadata, not an ArtifactId manifest.
Malformed administrative TOML, schema fields and manifest projection paths have
the typed `Manifest` cause. Translation is confined to interpretation of scanned
bytes; filesystem inspection and source safety failures keep their own causes.

The old activation code creates a projection symlink whose literal destination
is `<generation entry store path>/<manifest path>`. A source symlink listed by a
manifest is projected as a link to that source entry, not its dereferenced
destination. The old generation format uses integer `id` and `[[entries]]`
with string `package` and `store`. Existing generation codecs also support v2
and v3 memberships. Historical `current` is canonical decimal with an optional
single LF; its writer uses an ordinary text file, often mode 0644. D3 accepts
safe effective-owner regular current files with one link and no group/other
write or special permission bits. New D1 current records are not adoptable.

M2.5-C already recognizes a legacy store locator that is a symlink to a bound
`objects/v1/sha256/<64 lowercase hex>` object. There is no separate legacy alias
manifest writer. D3 retains the alias's exact literal bytes, resolves those
bytes with no symlink ancestry, and verifies the authoritative object's v1
identity. An object without an embedded historical manifest can be sealed as
an alias but cannot authorize the old path-only activation projection. This
fails closed rather than inventing a manifest. Realization memberships in a
mixed generation derive their projection from verified ArtifactIds instead.

Legacy locators must be canonical absolute paths below the exact bound store
authority, outside `objects/`, with exactly one matching generation membership.
Relative, normalized-on-read, duplicate, ambiguous, or external references fail.
Sources overlapping generation or projection authority are rejected before
sealing can create administrative state inside legacy content.
Package names alone never authorize a source. Manifests are parsed from the
same scanned bytes that are sealed; only `files` and only `path` in each table
are allowed. Duplicate paths, missing payloads, directory references,
administrative paths, unlisted non-directory payloads, and conflicting metadata
fail. The historical TOML bytes need not have D1's canonical spelling: their
exact bytes are bound into the inventory. Metadata keys and types are strict,
required historical string fields are nonempty, and the package association
must match the generation. Historical source/archive strings retain their
existing meaning; they are not reinterpreted as payload identity.

## Inventory and seal identity

`artifact::scan_bounded` scans an already pinned descriptor twice. It uses the
existing artifact metadata, permissions, hardlink, xattr, ACL, inode-flags, and
unsupported-entry gates. The absence of hidden `trusted.*` xattrs still needs
initial-user-namespace CAP_SYS_ADMIN, unless the filesystem explicitly proves
xattrs unsupported. D3 adds no bypass. Alias metadata outside the payload tree
uses the same metadata safety gate.

Default/hard maximum limits per source are 65,536 entries, 4,095 bytes per
relative path or literal symlink target, 255 bytes per component, depth 128,
and 64 MiB aggregate path, target and regular-file bytes. Callers may lower
these limits. Entry and byte limits apply during enumeration/reading, not only
after allocation. Pending names reserve the same global entry budget before
recursion. The root is implicit. Every descendant must have the root's
statx mount ID; no fallback accepts missing mount information. Traversal does
not follow symlinks. Entries use artifact v1 unsigned-byte ordering and
normalized executable metadata; regular logical bytes, literal symlink bytes,
directories, and both administrative documents are included. Changes to
nonsemantic timestamps do not define a new content identity. Because legacy
activation retains the original source rather than materializing normalized
permissions, D3 additionally binds each node's exact Linux type, permission bits,
uid and gid, including the root. Non-executable access permission changes thus
invalidate a legacy seal even though they do not change an ArtifactId. These
metadata entries are unsigned-byte sorted by path; root uses an empty path.
Legacy nodes must have the effective owner, and files/directories may not be
group/other writable. Symlink mode 0777 is intrinsic and does not grant target
write permission. These D3-specific checks prevent unprivileged payload writers
from defeating the exclusion contract; the ordinary artifact scanner's
normalization contract is unchanged. Literal alias-prefix directories must have
trusted ancestor owner/mode metadata under the existing sticky-directory rule.
Runtime observations retain actual inode, device,
owner, mode, link count, size, mtime and ctime to reject substitution during
sealing; these observations are never serialized as durable identity.

The distinct D1 `LegacySealDigest` is reused. Let `U64(n)` be big-endian unsigned
64-bit encoding and `B(s) = U64(byte_length(s)) || s`. The SHA-256 preimage is:

```
"athena.legacy-seal.v1\n"
|| B(generation_authority)
|| B(store_authority)
|| B(source_locator)
|| B("legacy_tree" or "legacy_alias")
|| B(alias_literal or empty)
|| B(artifact_id spelling or empty)
|| B(U64(locator st_mode) || U64(locator uid) || U64(locator gid))
|| B(generation-associated package bytes)
|| B(artifact v1 canonical inventory bytes)
|| B(legacy metadata bytes)
|| U64(number of manifest projection paths)
|| B(path[0]) || ... || B(path[n-1])
```

Manifest paths are unsigned-byte sorted. Artifact canonical bytes use the
existing v1 framing and contain the administrative manifest bytes and normalized
entry contents, so this is not a path-only hash. The result uses `sha256:` plus
64 lowercase hex digits, with a semantic type distinct from ArtifactId,
GenerationDocumentDigest and PlanDigest. Generation number is not part of the
source seal; exact generation-document identity is separately bound by adoption.

Legacy metadata bytes are `U64(node count, including root)` followed, in
unsigned-byte path order, by `B(path) || U64(st_mode & S_IFMT) ||
U64(st_mode & 07777) || U64(uid) || U64(gid)` for every node. Linux namespace-visible
owner IDs are used under the same authority/namespace deployment contract as
the existing locking helpers. No inode, device, mount ID or timestamp appears
in the durable digest.

## Durable sealing and revalidation

`seal_legacy(context, State, generation, locator)` validates both D2 authority
records, exact generation membership, safe ancestry and complete inventory.
Its separate descriptor-relative generation reader reuses the frozen D1
generation codec, rejects mount crossings and unsafe owner/mode/link metadata,
and opens documents with O_NONBLOCK before rejecting nonregular entries. Thus
a malformed FIFO cannot block before validation. D1 codec contracts are unchanged.
It synchronizes all regular payload and administrative files, then descendant
directories in reverse canonical order, the source root and parent, store
ancestors and required store parent. It reopens named ancestry and checks the
generation document and source identity. It scans again and compares both
content and runtime observations across the barriers.

An exact seal record is published without replacement at:

```
<generation-authority>/.athena-legacy-seals/<64 digest hex>.toml
```

The private namespace is mode 0700; records are effective-owner mode 0600,
regular with one link. Fixed record key order is `schema_version` (integer 1),
`seal_digest`, `generation_authority_hex`, `store_authority_hex`, `kind`,
`source_mode`, `source_uid`, `source_gid`, `locator_hex`, `alias_target_hex`, `artifact_id`, `package_hex`,
`inventory_digest`. Tree alias/artifact fields are explicitly empty strings.
Inventory digest is SHA-256 of `"athena.legacy-inventory.v1\n" ||
B(artifact canonical bytes) || B(legacy metadata bytes)`.
Only equality to a freshly constructed canonical record is accepted.

Record creation uses an exclusive private directory, complete write, file
fsync, preparation-directory fsync, final source/authority checks,
RENAME_NOREPLACE, and both directory barriers. Published records, seal directory,
generation authority and its parent are synchronized; inventory and record are
verified again. Exact existing records are resynchronized, never overwritten.
Private preparation residue is retained and never treated as a seal. No legacy
payload is rewritten. Administrative cleanup is deferred.

`verify_legacy_seal` is separate and namespace-preserving, but it is deliberately
not read-only I/O: every verification synchronizes the currently opened source
instance. It repeats authority, membership and bounded inventory validation,
compares the full expected D1 source representation, completes the same payload
and source-namespace barriers as sealing, requires the exact published seal
record, and resynchronizes that record and its administrative parents. It never
creates a missing seal namespace/record or overwrites a conflicting record.
`SealMismatch`, `UnsafeSource` and `Durability` are separate typed causes. A failed
required barrier never authorizes the source; after barriers begin, failure is
conservatively OutcomeUncertain, including recovery attempts.

### Current-instance provenance correction

The earlier read-only verification path could accept an identical replacement
using barriers performed on the retired instance. The correction evaluates:

* A: resynchronize the current instance on every durability-requiring use;
* B: retain descriptors and a verified durability proof across the full operation;
* C: combine fresh synchronization with an authority-bearing retained handle.

A is selected: it avoids a second public handle lifecycle, global caches and
persisted runtime identities. Root, alias inode, parent and source-namespace
ancestor descriptors are retained during each verification, as ordinary safe
implementation mechanics. Every regular-file and directory barrier validates
its descriptor against the initial scanner observation before and after fsync.
Fresh bounded scans compare contents and all runtime observations across the
barriers and administrative validation. Source and alias/object ancestry are
reopened without symlinks or mount crossings and compared with retained
descriptors. Both locator-parent and alias object-parent chains are synchronized.
For aliases containing literal directory detours before `..`, every actual
literal prefix directory is retained, synchronized and revalidated too; lexical
normalization is never used as durability evidence. Alias namespace prefixes are
bounded by the scan depth limit. This preserves the exact alias bytes.
The store namespace parent is retained/revalidated too. The published seal record
descriptor remains pinned through final validation so a same-byte record
replacement cannot borrow another record inode's fsync.

Four facts remain distinct: the digest describes content/metadata identity;
runtime observations identify this operation's filesystem objects; successful
barriers establish durability for these objects; authority binding and exact
generation membership authorize their use. The record proves explicit sealing
authorization, not that any future reopened instance inherited old barriers.
An identical replacement has the same digest but must receive its own complete
barriers before verification succeeds. Relevant modification fails the expected
digest comparison. No inode, device or mount ID is persisted as durable identity.

The caller must retain exclusive State and exclude equivalent-authority external
writers throughout verification AND the operation relying on its result. Returned
inventory values are not reusable durability capabilities after that boundary
ends. Each later operation verifies again. Within one adoption, source verification
runs before preparation, before publication and after publication; exact published
retries verify both before and after their barriers. D2 adoption-witness resolution
also performs current-instance verification under its existing caller-held State
contract. Cooperating Athena participants cannot change the authority while State
is held. Legacy/raw store helpers do not all acquire this authority's State lock;
the caller must also quiesce those helpers as non-cooperating writers. State alone
is not a filesystem snapshot. Hostile privileged writers remain outside the
frozen exclusion contract. D3 does not add D8 command integration to arrange that
exclusion automatically.

Modern ArtifactSource memberships continue to require M2.5-B/C immutable
publication and store authority. D3 does not permit replacement of immutable
objects under that contract. Legacy aliases nevertheless resynchronize their
actual resolved object instance on every seal verification.

## Adoption authorization and record v1

The caller supplies an unforgeable exclusive `ProjectionState` for the exact
generation authority and the expected legacy seals, in generation membership
order. Adoption does not acquire State recursively. Alias and realization
verification acquire StoreGc only after State. If a TransactionLease is held,
it must already precede State. No new activation lock is introduced.

Adoption reads historical current, validates its exact generation document,
revalidates all source seals, derives the full expected projection, checks both
D2 authority bindings, and scans the complete projection root. Every expected
link must exist with its exact literal destination and effective owner; all
expected directories must be real directories on the projection mount. Extra
symlinks, regular files, unsupported entries, unsafe ancestry, mount crossings,
duplicate projection paths and conflicting links fail without mutation. Empty
real directory scaffolding may remain. Each managed symlink is pinned with an
O_PATH/O_NOFOLLOW descriptor to prevent inode reuse during preparation. Current,
generation, source seals, parent ancestry and original managed inode identities
are checked again before publication.

Canonical adoption TOML is bounded to 16 MiB. Top-level keys have this exact
order:

```
schema_version = 1
adoption_id = "<32 lowercase hex>"
projection_id = "<32 lowercase hex>"
generation_authority_hex = "<raw absolute bytes in lowercase hex>"
store_authority_hex = "<raw absolute bytes in lowercase hex>"
projection_root_hex = "<raw absolute bytes in lowercase hex>"
generation = <nonnegative int64>
historical_current_hex = "<exact historical decimal bytes in hex>"
generation_digest = "sha256:<64 lowercase hex>"
directories_hex = [
    "<relative path hex>",
]
```

Empty `sources = []` and/or `entries = []` follow the directories array when
needed. Nonempty sources are `[[sources]]` tables in authoritative legacy
membership order, followed by deduplicated realization ArtifactIds in the
generation's deterministic realization order. Each tree table has `kind`,
`locator_hex`, `seal_digest`; alias tables add `alias_target_hex`, `artifact_id`
between locator and seal; artifact tables have only `kind`, `artifact_id`.
These reuse D1's source types. Kind spellings are `legacy_tree`, `legacy_alias`,
and `artifact`.

Nonempty entries are `[[entries]]` tables, in unsigned-byte projection path
order, with keys `id`, `source`, `path_hex`, `target_hex`, `witness`. IDs are
contiguous canonical decimal integers starting at zero. Witness spelling is
exactly `adoption:<adoption-id>:<entry-id>`; its path is derived internally.
Source indexes bind the destination to the source locator plus the projection
path. Directory paths are unsigned-byte sorted and unique; link ancestors must
be present and no directory may descend through a projected link. There are
at most 65,536 sources, links and directories. Unknown keys, wrong types,
duplicate IDs/paths, alternative hex or decimal spellings, comments, defaults,
reordered keys and missing final LF fail parse/serialize equality.

## Preparation, publication, witnesses and retries

The only projection administration root is D2's `.athena-activation`:

```
.athena-activation/adoptions/
    .preparations/<adoption-id>/
        adoption.toml
        witnesses/<entry-id>
    <adoption-id>/
        adoption.toml
        witnesses/<entry-id>
```

All administrative directories are effective-owner mode 0700; records are mode
0600. The complete expected record is written and synchronized privately before
witness preparation. `linkat(..., flags=0)` hard-links each validated historical
symlink inode itself into `witnesses`, never its target. Every witness-directory
barrier is followed by target, owner, mount and runtime inode relationship
validation. There is no link-count-one requirement on these projection links.
The complete witness inventory and record are checked, all required preparation
barriers completed, and historical authority revalidated before publishing the
whole prepared directory using RENAME_NOREPLACE. Destination, preparation parent
and administration parent barriers follow. No overwrite fallback exists.

Preparation never proves ownership. Exact retry validates record equality,
private shape, all existing witness relationships and current historical
authority before reusing anything. Missing/partial records, extra entries,
different IDs, alternate targets and independently created identical-target
witnesses are conflicts. A valid exact partial witness inventory can resume.
An empty/incomplete namespace left before record completion fails closed and
is preserved; D3 does not guess its provenance or repair it. An exact published
retry revalidates all managed/witness relationships and re-establishes its
barriers, including the current published record file and both publication rename
parents (`adoptions` and `.preparations`), then returns NotMutated. Publication
and published retry share the same parent-barrier sequence, with retained parent
identity checks before and after synchronization. A failed recovery barrier or
parent substitution remains OutcomeUncertain and cannot return successful recovery.
Current-instance source barriers are completed again before successful return.
An independently recreated same-target
managed symlink fails the witness inode test.

Outcomes are NotMutated, MutatedDurably, and OutcomeUncertain. Any failure after
a preparation mutation or durability barrier is conservatively uncertain;
post-publication fsync failure is never classified as clean pre-publication
failure. Typed errors preserve errno where available and the underlying
exception. Failed operations retain preparation and historical projection.

D2 resolves adoption references only through the canonical published record,
exact projection binding, generation document, verified source seals and derived
expected projection. Its final ownership test still compares the managed and
witness inode/device/mount identity at runtime. Activation witnesses keep their
existing path, grammar and behavior. Adoption references cannot create new D2
links; the explicit D3 adoption primitive is the authorization boundary.

## Execution contract and testing

State coordinates Athena participants. Equivalent-authority external writers
must be quiescent throughout sealing, verification, adoption, witness validation
and any operation relying on the resulting inventory. This is
not an atomic snapshot against privileged hostile writers. Authorities and
their preexisting ancestors must be durable and trusted. The inherited local
Linux filesystem contract requires openat2/statx mount IDs, atomic
RENAME_NOREPLACE, symlink hard-link support and honest file/directory barriers.
The durable helper allowlist remains ext, XFS, Btrfs and tmpfs; overlay and
unknown/network filesystems remain unsupported. Tmpfs tests establish namespace
ordering, not reboot persistence. No physical power-loss qualification is claimed.

`legacy_d3_test` exercises codec, unsafe locator, bounded-inventory, empty
historical authority, operation-local write/rename/fsync failures and actual
publication state. Pipe-synchronized child termination tests both sides of
publication, then exec a fresh process to retry. `legacy_d3_scanner_test` contains
actual legacy tree and alias fixtures, sealing/stale inventory checks, populated
multi-link adoption, inode ownership assertions, conflicts, witness substitution
and all observed fsync boundaries. It reports return 77 separately when the
unchanged trusted-xattr scanner privilege gate cannot be satisfied. Syscall
callbacks are owned by each operation/context; there are no mutable global
production hooks.

`legacy_d3_test review-findings` independently targets the review corrections:
it injects EIO at the preparation-parent barrier after publication, fails each
of the six required published-retry barriers in a fresh context, and then checks
successful recovery's exact barrier order. Preparation-parent substitution during
recovery must fail uncertainly. Pure manifest interpretation tests qualify typed
syntax/schema/path errors without claiming scanner qualification; scanner-backed
manifest and metadata cases remain behind the unchanged privilege gate.

Provenance regressions copy/rename an identical source without any fixture fsync,
then record the actual descriptor device/inode pairs passed to operation-local
fsync. They require barriers for the replacement root, every regular file and
directory, namespace parents and existing record. Cases cover modified copies,
nested files/directories/symlinks, alias locator/object replacements, every
observed verification barrier failure, repeated failed recovery and successful
fresh recovery, substitutions during barriers, seal-record replacement, adoption
and exact published retry, and D2 ownership rejection on durability failure.
Privileged scanner-dependent cases must execute before those paths can be claimed
as empirically qualified; a skip is not a pass or power-loss qualification.

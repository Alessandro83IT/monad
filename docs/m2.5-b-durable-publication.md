# M2.5-B durable immutable publication

## Architecture audit

A. ArtifactId is SHA-256 over the canonical Artifact Schema v1 model/encoding.
Neither identity nor scanner policy changes. The scanner pins directories,
rejects symlink locator components, checks observations, special files, hardlinks,
permissions, capabilities and xattrs (including fail-closed trusted.* inspection).
Realization executor publishes its staging through ObjectStore, then records the
ArtifactId outside the payload; no administrative manifest belongs in the hash.
ObjectStore previously materialized and hardened `payload` within a private
`.publish-*` container beneath `objects/v1/sha256`, locally verified, renamed
NOREPLACE, then verified the winner. The rename was the visibility boundary;
there were no file/directory durability barriers. The detail rename primitive
is retained for existing focused tests; production uses the durable primitive.

B. GenerationManager previously created the final numeric directory and then
streamed `generation.toml` into it. Directory creation exposed incomplete state.
The generation codec supports historical and modern records; it is unchanged.
Allocation used stoull without full consumption and unchecked max+1. Both
initialize and create now lock allocation/publication with the namespace-derived
exclusive State lock. Numeric names are canonical decimal (0 or no leading zero);
links and auxiliary directories are ignored; IDs above the persisted TOML
signed 64-bit maximum (`INT64_MAX`) fail closed. Allocation from `INT64_MAX`
fails before any private preparation or publication, without unsigned wrap.
`list` uses the same parser. All valid persisted generations remain GC roots.
Allocation uses max retained ID + 1, not a persisted lifetime counter; discarding
the highest retained generation can permit ID reuse, as in the existing design.

C. Legacy `store::install` creates `<store>/<name>-<version>`, copies regular
files from staged `/usr`, then writes `.athena/metadata.toml` and manifest.
It deletes historical incomplete entries and follows source links according to
its existing copy behavior. Metadata/manifest writers serve this historical
path, not ObjectStore or the generation codec. This path still exposes incomplete
entries. Migrating it safely requires choosing compatibility behavior for
incomplete replacement, source links, legacy entry verification and GC readers;
that materially broadens this immutable ArtifactId/generation change. It is
explicitly deferred, without conversion to ArtifactId or legacy identity changes.
Modern realization uses ObjectStore directly and never uses this legacy partial
publication path to establish artifact durability. Generation publication
guarantees metadata durability; references to legacy payloads do not upgrade
those payloads to durable objects.

## Object publication

Validate source and expected ID, preflight the store, ensure/synchronize namespace
directories, allocate an exclusive random 0700 container with mkdirat under the
pinned namespace, materialize normalized contents and final read-only modes,
synchronize the tree, synchronize the container, scan/hash locally, rename
payload with RENAME_NOREPLACE, synchronize destination and source parents, and
scan/hash the winner. No copying fallback or authoritative-path construction.
The tree walk traverses validated model entries in reverse canonical order,
opens each parent without following links, fsyncs regular files after final
modes, fsyncs directories after descendants, and finally fsyncs the root.
Symlinks receive no data fsync; their parent barrier persists their namespace.
The private tree is caller-owned and quiescent; hostile/privileged mutation of
managed namespace entries or mounts remains outside the M2.5-A contract.

Namespace preparation, checked payload writes (including partial progress and
EINTR), private-name randomness, file/directory barriers, NOREPLACE rename,
both publication parents and existing-winner synchronization consistently use
the supplied per-operation Syscalls table. Production defaults are direct Linux
syscalls; there are no mutable global hooks. Directory opens, mkdir and chmod
remain direct operations outside the narrow injection table. Namespace setup
and payload materialization are shared with unprivileged focused tests; this
does not bypass the production scanner or assert ArtifactId eligibility.

`publish_durable` returns Published or AlreadyExists with the object locator.
The existing path-returning `publish` wraps it. EEXIST never changes the winner;
the destination barrier and existing Schema v1 identity/model verification must
succeed. A valid existing tree is also synchronized, covering pre-M2.5-B objects. Invalid winners retain integrity errors. Failed writes/barriers/renames
before visibility are NOT PUBLISHED. Failed barriers after visibility retain
PersistenceError's stage, errno and OUTCOME UNCERTAIN. Post-publication winner
verification failure is conservatively uncertain, with the original error nested.
Cleanup is descriptor-relative, private-only and best effort; secondary errors
are retained on persistence/object errors without changing the primary failure.
Cleanup after durable success cannot invalidate successful publication.

Object publication takes no broad authority lock: expensive private construction
is independent and competing publishers use NOREPLACE. Existing GC has no shared
store-lock protocol, so adding a one-sided lock would not coordinate it. This
phase does not claim protection against GC deletion between publication and a
future transaction root; transaction pins and GC coordination belong to M2.5-C.
No StoreGc-to-State acquisition or lock upgrade is introduced.

## Generation publication

GenerationManager initialize/create acquire exclusive State after safe directory
setup. The lock covers max+1 and publication; write_generation is private and
requires this lock. The lower-level testable persist helper requires its caller
to hold State; deliberate collision tests exercise NOREPLACE directly.
Write the existing serialized generation to an exclusive file in a random private
directory under the generation authority, complete_write, file fsync, private
directory fsync, same-parent NOREPLACE rename to the intended numeric ID, parent
fsync. Collision is an error and never overwrite. Published metadata needs no
new sidecar: atomic publication of a fully serialized/barriered file supplies
this phase's integrity requirement. Historical and modern decoding are unchanged.
Publication does not select current. Existing initialize/current/switch semantics
and the textual current-selection format remain unchanged and are not made
transactionally durable here. A generation can persist unselected.

Read-only list/enumeration and GC root discovery never initialize the namespace,
create directories, fsync, or require a filesystem supported for durable mutation.
A missing namespace is empty; unsafe traversal, inspection failures, out-of-range
canonical numeric directories and malformed authoritative metadata remain errors.
get/current open existing regular metadata through no-follow directory traversal.

Every published numeric generation is visible through list/get even if unselected,
is a GC root for all its legacy stores and ArtifactIds, participates in max-ID
allocation, and is a possible switch/rollback candidate under existing validation.
The list/get API does not require current. CLI `generation list` displays these
generations when current is readable, but still fails if an existing namespace
has missing/corrupt current. Installed-package `list`/`info` read only current;
an unselected membership does not make a package installed in those views.
CLI rollback specifically chooses the greatest retained ID below current. It
does not distinguish previously selected generations from unselected published
ones. An ID above current is not the immediate rollback choice; it may become
one after a larger ID is selected. No selected-history or commit marker exists.
These conservative roots prevent premature collection of retained memberships,
but publication is not proof that an environment transaction committed.
The generation metadata and separate current pointer remain available for later
recovery design; historical selection provenance cannot be reconstructed from
them alone. Current commitment, durable selection history (if required) and
startup reconciliation remain M2.5-E/F. In particular, a crash after publishing
generation 0 but before writing current can make initialize retry collide.
No repair or transaction selection protocol is introduced here.

## Filesystem and future work

Reuse M2.5-A's ext-family/XFS/Btrfs/tmpfs allowlist. Unknown, overlay, network and
FUSE classes fail before publication mutation; no weaker rename or fsync fallback.
Existing ancestors, trusted namespace ownership, supported mount options and
honest storage barriers remain prerequisites. tmpfs tests prove ordering/error
behavior only. SIGKILL boundaries are process-death tests, not power-loss tests.
Private leftovers after crashes/cleanup failures are nonauthoritative; no sweep
or startup recovery is implemented.

M2.5-C: durable transaction pins and recoverable GC.
M2.5-D: durable activation plans and reconciliation.
M2.5-E: authoritative selection and integrated install/remove commits.
M2.5-F: recovery, migration and fail-closed startup.
M2.5-G: crash/storage-failure and actual power-loss qualification.

Full scanner-dependent object tests retain the existing capability prerequisite
and report skip code 77 when hidden trusted.* inspection is unavailable.
Generation failures/concurrency/crash boundaries, the artifact durability walk
and byte-known artifact-tree SIGKILL boundaries through real preparation and
same-parent publication helpers remain runnable without scanner privileges. These tree tests
do not assert complete scanner eligibility; production retains the scanner gate.

Cross-parent rename of a read-only directory requires adequate Linux inode write
permissions (normally provided by the privileged Athena publisher). Permission
rejection is pre-publication and never triggers a copy fallback. Unprivileged
byte-known tree crash tests use same-parent publication; the complete ObjectStore
flow remains in the scanner-dependent test.

GenerationManager binds its authority locator to an absolute path once at
construction, removing only empty and `.` components. Trailing slashes and
ordinary `./` spellings work in both constructors. `..` is rejected rather than
lexically collapsed, so normalization cannot hide a required symlink inspection.
Actual traversal is no-follow. Later cwd changes cannot redirect allocation,
publication or reads away from the State-lock namespace. Subprocess tests cover
both constructor forms and reject symlink authority components.

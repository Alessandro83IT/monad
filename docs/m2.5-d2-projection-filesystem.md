# M2.5-D2 projection filesystem authority

D2 is an isolated internal foundation. Legacy activation and
`GenerationManager::switch_to` retain their existing behavior. No v1 live
selection, durable plan, adoption, reconciliation, GC or pin integration is
introduced here.

## Authority and locking

`ProjectionBinding` uses the D1 distinct `ProjectionId`, native byte locators
encoded as lowercase hex, exact keys, an actual TOML integer version 1, and
byte-canonical serialization. The projection record is
`.athena-activation/authority.toml`; its matching generation record is
`.athena-projection-authority.toml`. Opening requires both exact records and the
supplied ObjectStore's exact canonical authority. Validation never initializes.
A context retains generation, store, projection, admin, witness and work
fds plus runtime mount identity. Revalidation verifies that durable locators
still name those authority objects and named private directories still name
retained descriptors. No inode, device or mount identity is persisted.

`ProjectionState` explicitly owns the existing namespace-derived exclusive State
lock. Binding creation and mutations require that token and verify its generation
authority. Acquire it after TransactionLease and before StoreGc. The filesystem
module does not acquire State through public manager methods or invent another
activation lock. Read-only opening/validation does not acquire locks; callers
requiring a consistent snapshot hold State themselves.

Athena operations serialize with State. Non-cooperating writers with equivalent
mutation authority must be quiescent during mutation critical sections. Named
identity revalidation narrows avoidable races; it cannot make POSIX validate-then-
rename/unlink conditional on an inode. This is not a claim to resist concurrent
same-authority namespace replacement. Ordinary payload directories need not be
read-only. Privileged mount changes are outside the supported contract.

## Initial binding and partial state

Explicit `create_binding` requires the generation record and reserved projection
namespace both absent. It exclusively creates the reserved mode-0700 directory,
then its witness/work roots. Records are completely written to exclusive mode-
0600 regular files in random private preparation directories, fsynced, and
published with true NOREPLACE. Both changed directories are synchronized. Only
own empty preparation directories are removed, followed by a parent barrier.
There is no recursive error cleanup or adoption of conflicting entries.

The projection-side record is published first, then the generation-side record.
There is no cross-filesystem atomic transaction. Any incomplete reserved
namespace or one-sided binding rejects ordinary opening and fresh creation.
Failures preserve private preparation and published facts for inspection. D2
has no automatic recovery or finish-known-binding API. Exact complete records
visible after an uncertain barrier may be opened, but their visibility does not
prove the failed barrier succeeded. No D6 initialization semantics are implied.

## Protected namespace

The administration directory, witness/work roots and activation containers are
real directories, effective-uid owned, exactly mode 0700 (including no special
bits), on the projection mount. Binding files are effective-uid owned, exactly
mode 0600 regular files with one link. Creation does not chmod/chown foreign
entries. Symlinks are effective-uid owned; their conventional mode is not used
as access control. Witness symlink link counts may exceed one and are not an
ownership restriction. Parent/private descriptor identity is revalidated.

The admin root has exactly `authority.toml`, `witnesses` and `work`. `adoptions`
is reserved for D3 and rejected in the D2 layout. Witness/work roots contain
only canonical activation IDs naming protected containers. Containers contain
only canonical nonnegative int64 decimal names naming symlinks. Unexpected
state fails closed and is never recursively deleted. A preexisting reserved
namespace is a creation conflict even when empty and mode 0700.

Only `.athena-activation` at the projection root and its descendants are
reserved payload paths. `.athena-activation-old` and `foo/.athena-activation`
remain legal. D1 path grammar rejects absolute paths, dot/dot-dot, NUL, empty,
repeated and trailing components, and overlong components/paths.

## Traversal and mounts

Projection traversal and binding record opens require Linux openat2 with
RESOLVE_BENEATH, RESOLVE_NO_SYMLINKS, RESOLVE_NO_MAGICLINKS and RESOLVE_NO_XDEV.
Directory opens include O_DIRECTORY, O_NOFOLLOW and O_CLOEXEC. Named
multi-component directory revalidation also uses constrained openat2 rather
than statx on a path whose intermediate components could follow symlinks.
There is no pathname fallback on unsupported kernels. Descriptor-relative
statx uses no-follow metadata and requires mount identity. Mount ID and device
identity must match the retained projection root, including for same-device
bind mounts. The projection root itself may be a mountpoint and must already
exist as a real directory. Root ancestry uses the existing no-follow foundation;
Athena does not provision or manage arbitrary root ancestors.

Durable mutation uses the existing local filesystem allowlist: ext, XFS,
Btrfs, tmpfs. tmpfs supports ordering mechanics, not reboot persistence.
Honest storage barriers and the existing supported filesystem contract remain
prerequisites. No existing regular-file/tree publication primitive gained
symlink acceptance.

## Persistent ownership and CREATE

A witness reference is derived exclusively from D1
`activation:<activation-id>:<operation-id>` into
`witnesses/<activation-id>/<operation-id>`. Adoption references return explicit
UnsupportedWitnessKind. Callers never supply witness paths.

A witness is a hard link to the symlink inode itself, created with linkat flags
zero, never AT_SYMLINK_FOLLOW. Ownership checks require both entries to be
symlinks on the expected mount, effective-uid owned, with the exact expected
literal destination bytes and matching runtime inode/device/mount identity.
Destination equality alone is insufficient: an independently created identical
symlink is foreign. Keeping the witness inode alive also prevents that inode
from being reused while the witness exists. No ctime stability or link-count-one
assumption is made.

Literal destinations are never resolved or normalized. Relative, absolute,
dangling, dot-dot and high-byte targets work. readlinkat buffers grow on a full
buffer because truncation has no explicit indicator. Embedded NUL, empty and
overlong destinations reject before mutation.

CREATE performs:

1. Exclusive witness symlink creation or exact private-witness validation; witness directory fsync.
2. linkat flags zero into deterministic private work name (or validate an existing exact witness inode); work directory fsync.
3. Context, private container, work/witness inode and destination parent checks.
4. RENAME_NOREPLACE into the managed name.
5. Destination parent fsync, then work directory fsync.

Exact private witness/work preparation may be resumed after a failed attempt; conflicting targets or work inodes fail closed. This never adopts a managed destination.

Mutation reuse first validates the activation container, then synchronizes the
container and its witness/work root, in that order. These barriers run even for
existing containers because a previous mkdir parent barrier may have failed.
Recovery barrier failures remain OutcomeUncertain and preserve all state.
Read-only container inspection performs no barriers.

No temporary name is created in an ordinary payload directory. Existing regular
files, directories and foreign symlinks remain untouched, including identical
targets. The work name is consumed on successful rename; persistent witnesses
remain available to inspect the managed inode. No rollback follows failed
post-mutation barriers. Symlink inodes are never fsynced as regular files;
namespace directory barriers establish the supported ordering.

Succession validates old ownership, links the managed symlink inode into an
exclusive successor witness name, synchronizes that witness directory, and
validates successor ownership. The projected name and predecessor witness remain. An exact existing successor is validated and synchronized without a namespace mutation.

## Outcomes and injection

`ProjectionError` independently carries cause, errno and namespace outcome:
NotMutated, MutatedDurably or OutcomeUncertain. These outcomes cover private
namespace preparation too, not merely changes to the managed destination. For
example CREATE EEXIST after durable preparation is ProjectionConflict /
MutatedDurably: the destination remains unchanged but witness/work entries
exist durably. Successful namespace mutations followed by failed required
barriers are OutcomeUncertain. No result rolls back uncertain state.
Binding errors conservatively report uncertainty once partial initialization
has progressed. Unknown durable state is never reported as no mutation.

`ProjectionIo` owns per-operation std::function callbacks for openat2, statx,
symlinkat, linkat, readlinkat, renameat2, mkdirat, unlinkat and fsync. Contexts
own their injection table; callbacks must own or safely retain their captures,
obey errno conventions and never throw. Existing Syscalls supplies durability
preflight, complete writes, random private preparation and descriptor RAII.
There are no mutable global production hooks.

Tests exercise Linux symlink hard-link semantics, strict bindings, namespace
security, identical foreign symlinks, mount/owner injection, all binding and
CREATE barriers, succession errors, container mkdir errors and barriers.
Independent-process tests acquire separate State locks and serialize shared-container creation. SIGKILL mechanics use pipes and mutation barriers, followed by fresh exec
inspection; no correctness sleeps are used. This demonstrates process-death
namespace mechanics, not crash/power-loss qualification.

Checked remove, replace and payload ENSURE_DIRECTORY primitives are deferred.
Future reconciliation must forbid directory-to-symlink conversion, recursive
payload deletion, or treating empty directories as owned. D3 through D10 retain
responsibility for adoption, plans, GC, live selection, reconciliation, handoff,
retention and broad crash qualification respectively.

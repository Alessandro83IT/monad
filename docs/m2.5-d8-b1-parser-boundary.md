# M2.5-D8-B1 — shared preventive TOML boundary

## Scope and architecture

The architectural authorization replaces the former H1-R1 blocker with a shared
incremental parser boundary. B1.2, B1.3, CLI integration and D8-B2 are not implemented
by this intervention. The historical `m2.5-d8b-cli-integration.md` is untouched.

The original toml++ 3.4.0 grammar is retained, with per-parser observer hooks before
allocation. This is not a second TOML lexer, a global allocator replacement, or a
post-`toml::parse` size check. A partial AST may contain already authorized nodes;
unknown keys and incompatible value/container types are rejected before parsing
their bodies. Resource checks precede every scalar/container node creation, array
element, implicit/dotted table, copied key, decoded string growth and recursive
value descent. Container contexts are attached immediately after authorized
construction. No process-global state is installed.

The implementation is a complete, private 51-header fork of toml++ 3.4.0 under
`third_party/athena_toml`, in the distinct `athena_toml` namespace. Namespaces,
friends, templates, inline functions, macros and header guards are isolated;
remaining implementation headers never fall through to the installed dependency.
No alias makes the original and fork AST types interchangeable. The fork is a
PRIVATE core include and is absent from installed public headers and consumer
include flags. The independent config/package/manifest loaders retain upstream.
Original and fork headers can coexist in either order in the same translation unit.

`UPSTREAM.sha256`, `observer.patch` and `vendor.py` reproduce the complete fork
from exact upstream headers: verify hashes, apply the observer patch without fuzz,
then mechanically isolate identifiers and include paths. A version assertion pins
3.4.0. See `third_party/athena_toml/README.md` for attribution, MIT license and the
mandatory upgrade review. Structural and object-symbol tests complement the runtime
consumer; neither is described as a mathematical proof for every ODR configuration.

## API and budgets

`src/parsing/bounded_toml.hpp` exposes:

- `parse(input, Profile, Budget, Stats*)`: typed incremental authorization.
- `parse(input, Profile)`: conservative source-derived compatible budgets.
- `parse_model(input, Profile)`: maps frontend errors to the existing model error.
- `parse_file(path, Profile, max_input_bytes)`: checks file size before allocating
  input storage and rejects growth or incomplete reads. It provides no filesystem
  ownership, inode, symlink, mount or lock authorization.

Explicit `Budget` fields bound input bytes, nodes, aggregate array elements,
structural/value depth, decoded token bytes and aggregate text work/key storage.
Checked subtraction prevents counter overflow before mutation. Stats are returned
on success and rejection and count authorization events, not heap bytes or RSS.

For B source bytes, compatible budgets are B+1 nodes, B array elements, B+1 depth,
B token bytes and 8B+1 text work; construction rejects arithmetic overflow. Root
accounts for the extra node. Every other node requires source syntax, and implicit
tables require distinct key segments. Decoded strings cannot exceed source length.
Text work includes decoded growth, recorded source and copied key segments; these
are a constant number of passes over source bytes. toml++'s existing nested-value
limit remains unchanged. No smaller general metadata cardinality quota is added.
The original 65,536 source/operation/adoption/manifest limits and six unique active
roles are enforced before the next array element. String limits already required
by identities and hex path contracts are checked during decoding.

Schema keys and types mirror existing validators. Dynamic feature names remain
unrestricted within source budgets. Fixed-schema unknown names are rejected while
decoding after 32 bytes, longer than every accepted schema key. Escapes are handled
by the same original parser; checks see decoded keys and strings. Comments, CRLF,
BOM, quoted/dotted keys, literal/basic strings and accepted inline/AoT syntax retain
the original grammar. Duplicate keys and malformed/truncated input remain TOML
errors. Necessary required-field checks at inline-table closure and before the
next AoT element prevent repeated incomplete-table amplification; a previous AoT
element cannot subsequently be extended under TOML semantics. Existing validators
still check schema versions, conditional requirements, enums, identity and digest.

Early rejection can change precedence for multiply invalid input. In particular,
unknown keys in an oversized array now fail Schema before reaching Bounds; two
schema tests accept either early rejection. Oversized identity strings preserve
Identity, rather than incorrectly becoming Bounds. No valid-input limits changed.

## Reachable parser map

| Path | Protected parsing |
| --- | --- |
| B1.1 public factory/encoder/decoder | Envelope constant-storage scan; decoded intent and plan through activation codec; exact generation documents through generation codec |
| D8.1 reconstruction | Intent, plan, current, binding, status and adoption profiles; source generation validation; realization records; installed semantic/policy subdocuments; package metadata |
| D8.2 rivalidation and activation | Same shared entry points for persisted claims, generation bytes and identity reconstruction; TransactionPins/store binding reads |
| D8 legacy source authorization | Scanned manifest and metadata profiles; selection's legacy semantic capture and its indirect store metadata read use the existing 16 MiB document bound |
| Encoder subtree reconstruction | Generation record/semantics/policy, realization semantics, installed package subtree reparses use corresponding profiles |

`codec_detail::parse` preserves existing outer byte limits before entering the
frontend. Generation, realization, installed semantic/policy and package codecs
use typed model adapters. Nonoperational repository decoding and legacy one-argument
file APIs use the generic profile to preserve their existing permissive behavior;
they do not supply D8 authorization. Store manifest/scanner parsers outside these
operational paths are not newly qualified as protected D8 entry points.

H2's 16 MiB exact generation documents, B1.1 384 MiB envelope and 192 MiB decoded
aggregate budgets remain unchanged. Encoder hex expansion and aggregate overflow
checks remain local to B1.1. Historical document bytes are retained independently
of parsed models, including comments and CRLF; hashing uses the exact original
bytes. H3 snapshots caller-owned nested values before normalization/transfer and
rebuilds D8.1 PlanIdentity before serialization. Claims do not become filesystem
capabilities, authority or independent evidence of authorization. There is no
change to activation, retry, recovery, locks, ownership, digest or rebase semantics.

## Memory, time and residual risks

Only the outer canonical envelope scan has O(1) auxiliary storage. The shared
frontend stores one context per authorized container, O(C), plus the original
parser's bounded lookahead, key/string buffers, tracking vectors and recursive
stack. AST memory is O(N + decoded text + copied keys), allocator overhead excluded.
Typed unknown/wrong-type payloads cannot allocate their entire hidden subtree.
Rejected input may still allocate the authorized prefix and bounded key buffers.

The parser uses table map lookup and tracking-vector searches inherited from
toml++; no global linear-time guarantee is claimed. Large table sets can entail
superlinear lookup/search work. Original validators, subtree formatting/reparsing,
model copies, exact byte snapshots and hex encode/decode can coexist and add peaks.
Compatible source-derived budgets intentionally allow large valid documents. They
are not a hardware-safe heap quota, a global live-memory limit or an RSS bound.
Lower accepted metadata quotas or process isolation would be separate contract/
architecture decisions; neither is silently introduced here.

## Legacy errors and maintainability

`store::read_metadata(path)` retains `std::runtime_error` with the store path for
open failures, malformed syntax, incomplete reads and frontend rejections. The
bounded overload has the same error boundary. `metadata_detail::read_metadata_stream`
is internal and shares the production conversion/error path with deterministic
short-read/growth tests; no racing writer or privileged filesystem is required.
Generic one-argument reads remain permissive about extension fields.

Cardinality and encoded path/current limits now use existing activation constants.
ID/digest lengths are shared with the identity validators. Field names, types and
necessary completion requirements remain an explicit frontend mirror of model
validators: updating a model requires reviewing that mirror. No schema version,
identity rule, accepted-document quota or operational authority is moved here.

## Qualification

`bounded_toml_test` exercises unknown embedded arrays (32/4096 leaves) across typed
profiles with only the root authorized, inclusive/exclusive reduced node/array/
token/input budgets, depth and aggregate work, unknown dotted headers, long keys,
wrong container types, incomplete tables, malformed/truncated prefixes, arithmetic
overflow, historical schemas, BOM, escapes, Unicode, CRLF, comments, repeated policy
AoT and nested semantics with dynamic feature names. Guarded and observer-free
parsing produce equal trees for positive fixtures. This is compatibility evidence
for those fixtures, not an exhaustive proof for every TOML document.

The public codec regression now rejects the former embedded unknown-key attack
before scalar payload nodes. Its small ordinary-new observer reports requested
allocation bytes, not live heap or RSS. Existing codec tests cover H2's 8 MiB,
8 MiB+1 and 16 MiB exact-document boundaries, canonicality, digest preservation,
comments and H3 pre-move aliases, inventories, links, directories and witnesses.
Filesystem privilege-dependent tests and OOM stress are not executed on the MSI.

The stabilization qualification is reproducible with:

```sh
python3 tests/qualify_bounded_toml.py \
  --build-root /tmp/athena-toml-qualified \
  --output /tmp/athena-toml-evidence --jobs 4
```

Both paths must be new. The driver records an exact source SHA-256 manifest,
compiler/environment/configuration, commands, complete build/test logs, CTest
inventory, per-test JUnit PASS/FAIL/SKIP and NOT EXECUTED accounting, compile
commands, selected binary hashes and an evidence-file hash manifest. It checks
that the source file set and contents remain fixed during both builds. The explicit
versionable inventory `tests/bounded_toml_sources.txt` covers production, installed
headers, tests/fixtures, CMake, packaging, fork and this architecture document.
It includes the inventory itself and the qualification driver. Missing, modified,
symlinked and newly unlisted source inputs fail closed; only generated Python
`__pycache__` directories are omitted within the declared source roots.
Historical CLI reports are outside this documented build/test/security input
scope and are neither read nor required. No absent-file fallback is used. Final
results reports and generated evidence remain separate to avoid recursive hashes.
`qualification_driver_test` copies the real declared inputs into temporary trees
without the CLI report and verifies both successful closure and rejection of
missing, changed, unlisted, removed, symlinked or out-of-scope required inputs.
The driver also preserves complete CTest output beyond JUnit truncation.

`toml_upstream_probe` compiles only the original system 3.4.0 dependency, without
linking Athena. `toml_athena_probe` uses the guarded frontend. Their separate
processes compare acceptance and a fingerprint containing every node type,
key/string byte, integer, IEEE double bits and temporal value. Malformed-input
comparisons also require the original diagnostic text, preserving upstream literals. The versioned
`tests/toml_fixtures/matrix.tsv` currently contains 35 fixtures covering all 16
frontend profiles, historical generations, implicit/dotted tables, nested records,
AoT, dynamic long/Unicode names, escapes, CRLF, BOM, comments and repeated policies.
These are grammar/structural-profile fixtures, not a claim that alternate spelling
passes a codec's canonicality requirement. Full semantic/canonical identity checks
remain exercised by codec and operational regressions.

The matrix explicitly distinguishes malformed TOML from intentional structure and
identity rejection. Every positive fixture is also rerun with a zero-node budget
and must reject as Budget. Equality is finite differential evidence, not exhaustive
TOML conformance. The existing same-fork observer-free comparisons are supplementary.

`toml_upstream_consumer_test` uses only installed public Athena includes and upstream
in its consumer TU, calls library package codecs, and links two additional TUs that
include upstream/fork in opposite orders. Static assertions establish distinct node,
table, value and exception types. `toml_isolation_test` inspects compile commands,
public headers and defined symbols in every fork-using production object and the
original probe. Extended parser/observer definitions cannot inhabit `toml::`.
`toml_vendor_reproduction_test` checks the entire transformation, not just execution.

Dedicated D8.1 and D8.2 regressions reject unknown generation subtrees, including
D8.1 claims with a matching byte digest; D8.2 checks refusal before publication or
selection and successful activation after restoring valid persisted bytes. Existing
B1.1 regressions retain H1 preventive allocation checks, H2 exact 8 MiB/8 MiB+1/
16 MiB documents, H3 retained aliases, canonicality and digest reconstruction.

Privileged-label tests and `artifact_scanner_test` are excluded from the driver.
Safe prerequisite-dependent integration tests may report SKIP; these are not PASS.
The unregistered network test, OOM stress, physical privileged migration, B1.2/B1.3,
D8-B2 and power-loss qualification are NOT EXECUTED. No locks, recovery, ownership,
selection, digest framing or authorization semantics are changed by stabilization.
See `m2.5-d8-b1-toml-stabilization.md` for the actual final results and evidence paths;
older temporary-build counts do not qualify the current source snapshot.

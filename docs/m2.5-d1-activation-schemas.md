# M2.5-D1 activation identity and schema foundation

D1 adds internal immutable values, strict codecs and document identities only.
It does not change GenerationManager current reads/writes, projection activation,
GC, discard, transaction pins, installation or removal. No plan/status/witness
publication or recovery implementation is present.

## Modules

* `activation/identity`: distinct ActivationId, ProjectionId, AdoptionId,
  PlanDigest and LegacySealDigest types; bounded byte hex/path validation.
* `activation/current_selection`: HistoricalCurrent preserves exact digits plus
  optional one LF; CurrentV1 uses the frozen four-field schema.
* `activation/plan`: ActivationIntent, ActivationPlan, terminal ActivationStatus,
  witness-reference values, canonical codecs and combined plan identity.
* `generation/document`: validate/hash one exact document, or read it through a
  bounded no-follow reader with file/directory substitution checks. A caller
  reading live authority must supply State/lifetime serialization. The reader
  never acquires locks or mutates files. Its read callback is operation-local.

Headers remain internal; no exported API or mutation authority is introduced.
Values can be assembled in memory, but serialization always validates them and
never repairs ordering or inconsistent fields. Identity types have no invalid
default constructor; serialization also rejects invalid moved-from identities.

## Canonical bytes and limits

Writers use fixed field order, ASCII TOML, LF and a final newline. Parsers reject
unknown/missing/duplicate keys and wrong node types, then require exact equality
with canonical serialization. TOML acceptance alone is insufficient. Numeric
fields must be actual nonnegative integer nodes in the signed 64-bit domain.

Current input/output is limited to 4 KiB. Immutable activation and generation
documents and terminal status are limited to 16 MiB. Arrays are limited to 65,536
sources/operations; the parser checks counts before reserving decoded vectors.
Writers check their total byte budget on every append. Input length is checked
before TOML parsing.

Native paths are raw byte strings, serialized as even-length lowercase hex.
Relative paths reuse artifact grammar and are limited to 4,095 bytes, with
255-byte components. Absolute locators additionally require one leading slash,
canonical components and no trailing slash except `/`. NUL is forbidden in paths.
Spaces, tabs, newlines and non-UTF-8 bytes otherwise remain literal path bytes.
Alias targets are bounded NUL-free literal symlink bytes; their resolution,
containment and sealing are not certified by D1.

## Intent and plan validation

An intent binds generation/store/projection locator bytes, projection identity,
target generation/document digest, and a base variant. Selected bases contain
the exact current record, document digest and ownership namespace. Parsed base
generation/format must match decoded current; v1 ownership must match its embedded
activation ID. Decimal ownership is adoption or empty. Absent is representable;
generation-0 authorization belongs to D6.

Source identity order is kind spelling (`artifact`, `legacy_alias`,
`legacy_tree`), then unsigned identity bytes (ArtifactId or absolute locator).
The same identity cannot appear twice, including with different seal metadata.
Seal values are syntactic identities, not proofs that sealing occurred.

Canonical operation order is:

1. REMOVE: slash depth descending, unsigned path bytes ascending within a depth.
2. ENSURE_DIRECTORY: depth ascending, unsigned bytes ascending within a depth.
3. KEEP/CREATE/REPLACE: unsigned path bytes ascending.

IDs are contiguous in that order. Source references must be in range. New
witnesses must identify the plan's activation and their own operation. Old
witness references are syntax-checked; combined intent/plan hashing also checks
their namespace against base ownership. KEEP requires an unchanged source.
Duplicate old/desired links or directories, desired link/directory collisions,
link ancestors of desired entries, and REMOVE/CREATE encodings of replacement
are rejected. REMOVE/ENSURE_DIRECTORY at one path is representable.

The root `.athena-activation` administration prefix is reserved. Runtime
directory-to-link conflicts, root binding, generation membership/projection
completeness, source availability, inode ownership and witness existence remain
later-phase checks. A codec success confers no filesystem mutation permission.

Nonempty arrays use array-of-table headers. Root-level empty arrays precede all
headers, as required by TOML table scoping; sources precede operations otherwise.
Terminal status has only `complete` or `aborted`, with no mutable progress state.

## Digest framing

Generation document identity hashes:

```
"athena-generation-document-v1\0" || u64be(length) || exact document bytes
```

The existing generation decoder validates those same bytes and expected ID.
Historical documents are never reserialized for hashing. Reader checks preserve
existing no-follow/regular-file validation and detect replaced metadata or
generation directories and observable in-place changes during reading.

Plan identity hashes:

```
"athena-activation-plan-v1\0"
|| u64be(intent length) || canonical intent
|| u64be(activation length) || canonical activation
```

The activation IDs must agree. Status, derived target current and physical
witness/filesystem observations are excluded. Persisted witness references are
part of the immutable plan. No self-digest field or target-current field appears
in either hashed document, avoiding a digest cycle.

## Mechanics tests

`activation_current_test`, `activation_schema_test` and `activation_digest_test`
exercise accept/reject postconditions and categorized diagnostics, all schema
variants, byte preservation, limits, ordering/conflicts, independent fixed
SHA-256 vectors and deterministic read substitution. Checks remain active in
Release. No scanner capability bypass, correctness sleep or global production
fault hook is introduced.

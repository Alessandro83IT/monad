# M2.5-D8-B2 — immutable prepared-request archive

## Scope and authority

Baseline: `816e4fd48d31a1dbc81332eb9e36ad69159e3348`. B1 is consolidated.
B2 archives canonical B1.1 claims and recovers them under B1.3 revalidation.
It does not introduce a second activation journal, execution engine, selector,
terminal-status file, migration, bootstrap, CLI path or generation reconstruction.
The original D8.2 -> D4 -> D6 -> D7 path remains the sole execution route.

The caller explicitly provisions an existing durable private directory, owned by
the effective UID with mode 0700, in trusted no-symlink ancestry. It must be
dedicated to one configured ProjectionBinding, disjoint from and neither parent
nor descendant of the generation/store/projection authorities. B2 never creates
this directory, changes its permissions or infers ownership from serialized data.
There is no new binding initialization protocol. The directory's dedicated use
and configured binding are trusted caller configuration across restarts; they
are not discovered from a record. Each operation checks that configuration against
the live context and State; every recovered envelope must also match B1.3.

All operations require exclusive caller-held ProjectionState, ordered after any
TransactionLease and before StoreGc, and exclusion of equivalent-authority
archive writers and mount changes. No additional lock is acquired. The archive
retains pinned CLOEXEC root/parent fds and rechecks the configured path, including
ancestor substitution. Supported local filesystem validation reuses the existing
durability primitive; unknown filesystems, overlayfs and mount crossings fail.

An archive is NOT a D5/GC root. Caller generation/source lifetime protection and
transaction pins remain necessary until D4 takes its existing references. Missing
or changed generations after restart are rejected, never recreated from embedded
documents. This preserves the historical retention/locking/recovery contracts.

## Identity and API

`src/activation/operational_request_archive.hpp` defines:

- `RequestEnvelopeDigest`: a distinct SHA-256 type over the exact canonical B1.1
  envelope bytes; the B1.1 schema version is part of those bytes.
- `RequestArchiveReference { PlanIdentity plan; RequestEnvelopeDigest envelope; }`.
  PlanIdentity fixes D8 semantics and exact generation-document digests. The extra
  envelope digest fixes every original inventory/declaration byte as well.
- `identify_operational_request(prepared)`: derive a reference from an independently
  known complete request. It supplies identity, not authorization or retention.
- `OperationalRequestArchive::open(path, binding, io)`: validate and pin the existing
  configured directory. No mutation or State acquisition.
- `persist(context, held_state, prepared)`: B1.3 revalidation, canonical encoding,
  immutable atomic publication, or exact retry. Returns Published/AlreadyPublished.
- `recover(context, held_state, independently_expected_reference)`: read only the
  named ID, verify both expected digests and canonical B1.1 decoding, revalidate
  B1.3, repair archive barriers and return detached claims/publication disposition.

Recovery never learns its expected identity by enumerating candidates or reading
their self-declared hashes. No enumerate-and-activate API exists. A caller may
retain the reference in independently trusted operation context or recompute it
from the complete original request. Without such independent evidence B2 refuses
recovery; a filename, current symlink or decoded envelope is insufficient.

The envelope digest is necessary: redundant explicit parent directories can yield
the same canonical D8 plan while changing the canonical B1.1 envelope. PlanDigest
alone therefore cannot certify all original inventory bytes. A dedicated regression
demonstrates and rejects exactly this same-plan/different-envelope substitution.
Existing ActivationId, PlanIdentity, digest algorithms and B1.1 encoding are unchanged.

## Files, states and linearization

Only validated 32-lowercase-hex ActivationId forms filenames:
`.<id>.pending` and `<id>.toml`. Files must be effective-owner regular 0600 files,
single-linked, on the archive mount, at most the existing 384 MiB envelope bound.
No slash, user-selected leaf, symlink, FIFO, device, hard-link alias or mount
fallback is accepted. statx requires the identity/size/time/mount fields; bounded
pread compares named and opened observations and exact EOF before decoding.

| Observed state | Interpretation and permitted recovery |
| --- | --- |
| Neither name | Absent; no request is invented |
| Pending only, incomplete exact prefix | Unpublished preparation; reference-only recovery refuses; explicit persist with the independently known complete original request may append the missing suffix |
| Pending only, complete canonical bytes | With independent reference and fresh B1.3, repair file/directory barriers and promote without replacement |
| Final only | Visible published claims, not proof of an earlier barrier or activation; validate/revalidate and repair barriers |
| Both, identical complete bytes | Validate and synchronize final first; remove only the rechecked exact private pending residue and synchronize directory |
| Corrupt, unsafe, conflicting or stale | Fail closed; preserve records and original base; no truncation, overwrite, rebase or execution |

Persisting a partial preparation requires the COMPLETE original supplied request,
not merely a digest. The existing preparation must be an exact byte prefix and
its inode must remain unchanged. Writes append only; no existing file is truncated.
If final exists, both it and any pending residue must equal the full supplied
canonical bytes. Different bytes at the same ActivationId are an immutable collision.
Cleanup never deletes a final record, unknown names, conflicting or partial residue.

The publication visibility linearization point is renameat2(RENAME_NOREPLACE).
Durable success is returned only after final-file, archive-directory and immediate
parent barriers and identity rechecks. It means durable archive publication under
the supported filesystem/barrier contract, NOT authorized or completed activation.

## Write/barrier order and crash behavior

After authority checks and B1.3 revalidation:

1. Read existing final/pending with constrained openat2 and no-follow identity checks.
2. If necessary create pending O_EXCL mode 0600; conservatively arm archive uncertainty
   before the create syscall. No automatic failure cleanup discards uncertain residue.
3. Complete write with short-write/EINTR handling, or append a validated prefix suffix.
4. Re-read the exact prepared inode and bytes; repeat authority and B1.3 checks.
5. fsync pending file; recheck instance; fsync archive directory; recheck again.
6. rename pending to final with RENAME_NOREPLACE. Never replace a conflicting final.
7. Reopen final, requiring the same inode and exact bytes (rename may update ctime).
8. fsync final file; recheck; fsync archive directory; fsync its parent; recheck.
9. On the identical-final-plus-pending retry branch, perform step 8 first, then
   recheck and unlink only that exact pending inode; fsync archive; recheck final.

Before or during write a crash can leave absent/short pending data. Recovery cannot
infer missing bytes: it refuses until the original full request is explicitly
resubmitted. After complete write, fresh reference-only recovery can validate the
preparation and repeat all required barriers before promotion. A crash/fault after
rename may leave visible final with uncertain durability; visibility never skips
barrier repair. A cleanup crash leaves final plus residue or final alone, both
idempotently recoverable if bytes/identity match. Conflicts are never silently removed.

These namespace observations are exercised under process death and injected I/O
faults. Actual power-loss outcomes depend on the filesystem/storage contract and
are NOT qualified here. TMPFS is useful for process tests, not power-loss retention.
The caller-provisioned ancestor hierarchy must already be durable and quiescent;
syncing the immediate parent is not an arbitrary-ancestry durability proof.

## Errors, authorization and guarantees

`RequestArchiveError` retains stage, exception_ptr and an archive-local outcome
NotMutated/Uncertain. Uncertain is armed before mutation or barrier attempts and
does not assert whether any D8 selection occurred in an earlier attempt. Causes
and errno remain available in the underlying original exception. RAII only closes
fds; it does not delete records during unwinding. Recovery/persistence never calls
activate_prepared_operational, publishes a D4 plan, changes current or runs D7.

After recovery, execution is a SEPARATE independently authorized caller action:
`activate_prepared_operational(context, held_state, recovered.request)`. It always
uses unchanged D8.2 and fresh D6/D7 checks; no archive observation certifies payloads,
witnesses, ownership, selection durability or reconciliation. Stale requests and
exact-ID/digest retries retain their original base and documents through B1.3.

The archive assumes exclusive State plus a dedicated private directory and writer
exclusion. Checks detect tested substitutions; they do not solve arbitrary ABA,
malicious syscall providers, mount changes or hostile same-UID writers outside
that contract. No new aggregate RSS or disk quota is claimed. Parsing/encoding
retains B1 limits; hashing is linear and does not copy the envelope into a preimage.
No global journal scan/allocation or namespace-wide cleanup is introduced.

## Qualification scope

The dedicated nonprivileged test covers exact restart roundtrips; explicit D8
execution after recovery; selected retry; incomplete-prefix resubmission; digest
collision, same-plan envelope substitution, stale/missing generations; conflicting
residue; symlink/hardlink/FIFO/directory/permission/sparse oversized records;
root/file substitution; short reads/writes and EINTR; every write/fsync/rename
boundary before/after fault; cleanup faults before/after unlink and directory
barriers; fresh-process concurrent recovery; and SIGKILL at seven before/after
write/barrier/rename boundaries followed by new State and recovery.

Sparse oversized fixtures test size rejection before input allocation, not OOM
stress. Injected failures and SIGKILL are not physical power-loss experiments.
Privileged source/witness/mount/migration and hardware qualification are NOT EXECUTED.
Full clean Debug/Release qualification, B1/H1/H2/H3/D8 regressions and targeted
sanitizers are recorded separately with source/command/configuration hashes.
No B3/B4, CLI integration, archive deletion policy or recovery scheduler is included.

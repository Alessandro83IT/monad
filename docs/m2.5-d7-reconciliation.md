# M2.5-D7 — authorized reconciliation

Baseline: main at db0fced. This contract precedes functional implementation.

## Authority and transitions

An exact selected CurrentV1 plus the independently expected published D4 plan
authorizes only its validated membership transition. D5 retention is checked
before application. Generation documents, ArtifactIds and D3 seals must verify;
old and desired operation maps must equal the complete corresponding generation
projections, with no omitted or extra links. Declared sources cannot substitute
for generation membership. Parent directories are included in directory coverage.

REMOVE unlinks only an old witness-owned symlink, synchronizing its parent.
An already absent leaf is a satisfied final condition, after safe traversal and
a fresh parent barrier. Old witnesses remain. Missing parents are not silently
treated as successful removal.

REPLACE prepares a new witnessed symlink in private work, validates the exact old
managed inode immediately before atomic rename, then synchronizes destination and
work parents. An exact already-new inode is recoverable; an identical foreign
symlink is not. Directories and regular files are never overwritten.

ENSURE_DIRECTORY creates one real directory in a safely traversed existing parent,
then synchronizes directory and parent. An existing safe real directory is shared
scaffolding, never deletion authority. No chmod/chown, recursive removal or
directory-to-link conversion is authorized. CREATE and KEEP retain D2's witness
protocol, with recovery barriers for already satisfied operations.

Traversal uses D2 constrained openat2 and runtime mount identity. Symlink
ancestors, foreign owners on created/ensured directories, mount crossings and
ownership mismatches fail closed. Source symlink payload entries are projected
as literal links to the source entry; they are not followed by reconciliation.

## Recovery and integration

No mutable progress journal is necessary: immutable operations, persistent old/new
witnesses and exact current identify authority. Each operation recognizes only its
old authorized state or its desired final state. Repeated application repairs
required barriers. Ambiguous entries stop the pass and remain untouched; earlier
durable operations are not rolled back. Errors after any application progress
conservatively report OutcomeUncertain. Selection remains independent of payload.

Completion is returned only after a fresh verification of the entire desired
projection under the same State exclusion interval. A new selection requires
the predecessor's complete physical state. No terminal status publication,
automatic residue deletion, pin retirement or D9 cleanup is introduced.

## Limits and qualification

The trusted-namespace/external-writer contract of D2–D5 remains normative; POSIX
rename/unlink are not inode-conditional against equivalent-authority attackers.
Honest storage barriers and supported local filesystems are required. tmpfs and
SIGKILL demonstrate ordering/process mechanics only. D8 owns CLI migration and
transaction handoff; D9 owns cleanup/status policy; D10 owns power-loss testing.
Test matrix and Debian VM qualification instructions follow validation.

## Debian VM procedure — not executed on the Gentoo host

Use a dedicated Debian VM with root and CAP_SYS_ADMIN. Build Debug and Release
from this working-tree patch; committed baseline alone does not contain D6/D7.
The new tests are labelled `privileged` and return 77 for missing prerequisites.
A SKIP is not qualification. Mount guards require a successful ordinary unmount;
failure exits with failure and preserves the fixture without recursive cleanup.
No test formats a device. The ext4 fixture parent must already reside on ext4,
be root-owned mode 0700 and have no fixture mounts or unrelated content.

```sh
cmake -S . -B /tmp/athena-d67-debug -DCMAKE_BUILD_TYPE=Debug
cmake --build /tmp/athena-d67-debug --parallel 4
cmake -S . -B /tmp/athena-d67-release -DCMAKE_BUILD_TYPE=Release
cmake --build /tmp/athena-d67-release --parallel 4
# In the VM root shell only; existing ext4 filesystem, dedicated parent:
umask 0077
install -d -o root -g root -m 0700 /var/tmp/athena-d67-ext4
findmnt -T /var/tmp/athena-d67-ext4 -o TARGET,FSTYPE,OPTIONS
export ATHENA_D67_EXT4_TMPDIR=/var/tmp/athena-d67-ext4
ctest --test-dir /tmp/athena-d67-debug -R '^activation_execution_privileged_.*_test$' --verbose
ctest --test-dir /tmp/athena-d67-release -R '^activation_execution_privileged_.*_test$' --verbose
findmnt -rn -o TARGET
find /var/tmp/athena-d67-ext4 -mindepth 1 -print
```

Verify no mounts or fixtures remain under the test's `/tmp/athena-d6-*` paths or
ext4 parent. Requalify existing B/C scanner-backed integrations, D3 scanner and
D4/D5 privileged suites separately using their documented VM procedures; those
results cannot be inferred from these six cases. XFS, Btrfs and physical
power-loss behavior remain unqualified D10 coverage gaps.

## Architectural boundaries

Completion is observational under held State, not a persisted terminal record.
A missing/mismatching witness, corrupt source/plan or unauthorized entry is an
error rather than an invented `aborted` record. Inspection distinguishes only
safe complete/incomplete states; ambiguity retains its typed error and evidence.
D8 must supply explicit identity, transaction lifetime and migration orchestration.
D9 must specify terminal record placement, pin/plan/witness retention and cleanup
eligibility. Directory deletion/conversion remains intentionally unsupported
until deletion authority is defined. No unresolved destructive contract is
implemented by guessing. Equivalent-authority races and privileged mount changes
are outside D2–D5's supported exclusion contract, even when injected persistent
substitutions are detected by the tests.

Before applying even the first operation, D7 re-establishes the exact selected
current file and generation-parent barriers itself. It never infers durability
from visible CurrentV1 and never relies on an earlier caller's D6 recovery.
A current barrier failure prevents projection application. The nonprivileged
orchestration test covers this failure independently of primitive barriers.
`activation_selection_metadata_test` also verifies that both the manager observer
and D6 reject a current FIFO without blocking, including legacy initialization.
The legacy VM case additionally covers adoption-to-v1 KEEP, successor witnesses,
and rejection of a changed seal at the same predecessor locator before REMOVE.

REMOVE followed by ENSURE_DIRECTORY at the same path recognizes an already safe
final directory on replay, verifies the retained old witness, and synchronizes
the directory/parent. It never attempts to unlink that directory. The source VM
case covers the compound link-to-directory transition, repeated reconciliation
and refusal of the inverse directory-to-link conversion.

## Nonprivileged execution record — 2026-10-13

Baseline `main` at `db0fced62ed618430e449aaccc93cc0b04c8ee9c`, plus this uncommitted
D6/D7 working tree. Debug and Release builds succeeded, including all six VM-only
qualification modes. The full selected nonprivileged suite passed **93/93 in each
configuration, 0 FAIL, 0 SKIP**. Debug elapsed **161.68 s**, Release **79.52 s**.
There are 121 registered cases; 28 are deliberately excluded by the label/name
selection below, including the six new VM cases. Exclusion is not an executed
SKIP and not privileged qualification.

```sh
cmake -S . -B /tmp/athena-d6-debug -DCMAKE_BUILD_TYPE=Debug
cmake --build /tmp/athena-d6-debug --parallel 4
cmake -S . -B /tmp/athena-d67-release -DCMAKE_BUILD_TYPE=Release
cmake --build /tmp/athena-d67-release --parallel 4
ctest --test-dir /tmp/athena-d6-debug -LE privileged \
  -E '(scanner|integration|immutable_object_publication|generation_activation)' \
  --output-on-failure -j4
ctest --test-dir /tmp/athena-d67-release -LE privileged \
  -E '(scanner|integration|immutable_object_publication|generation_activation)' \
  --output-on-failure -j4
```

After final errno/bounded-metadata and compound-replay hardening, both builds
were repeated and the 10 affected nonprivileged cases were revalidated separately.
The privileged compound/source paths remain compiled but unexecuted. Logs reside
in each build's `nonprivileged-validation-final.log`,
`final-targeted-validation.log` and `checkpoints-d6-d7.log`. The latter preserves
both named D6/D7 checkpoint outputs, including the fault inventory and process
cases, before subsequent targeted CTest runs overwrite LastTest.log.

An initial parallel regression run exposed existing test-harness inventory races:
public_planning_test and resolution_result_test snapshot the build tree while
other tests create fixtures. Both complete sequential suites subsequently passed
92/92 before addition of the FIFO case. CMake now marks those two purity tests
RUN_SERIAL without weakening their assertions. The final 93-case parallel runs
above pass with that scheduling constraint. The initial Release build reports
only the existing ignored write return warning in core_foundation_test.cpp:135.

No mount, umount or privileged test was run on the Gentoo MSI. `/tmp` mechanics,
fault injection and SIGKILL do not qualify reboot/physical power-loss durability.
No commit or push was performed. `git diff --check`, including new-file checks,
and tracked plus new-file diff statistics are recorded in the delivery.

# M2.5-D8.2 — Durable Operational Activation Coordinator

Internal API: `activate_operational(context, held_state, request, expected_digest)`.
Baseline: clean `ceb5702` (D8.1). No manager, transaction-pin or D4–D7 changes.

## Composition audit

`generation::read_generation_document` supplies bounded no-follow exact-byte
identity observations without locking. D8.1 validates supplied bytes, membership,
source inventories, old witness ownership and canonical digest structurally.
`inspect_selection` validates context/State authority and observes exact current.
D4 publishes/recover-synchronizes the immutable pair. D6 independently recovers
that pair and validates live documents, source durability, membership, ownership,
witnesses and exact base before selection. D7 independently repeats authorization
and requires exact selected CurrentV1 before application.

One caller-owned exclusive `ProjectionState` spans every step; the coordinator
acquires no State or StoreGc itself. D6/D7 acquire StoreGc after State where needed.
No GenerationManager call is made. Existing context binding is mandatory; this
API does not bootstrap the binding or construct generations or source evidence.
The caller supplies an authorized request and preverified source inventories,
excludes equivalent-authority writers and mount changes, and retains generation
lifetime protection until D4 publication. D5 then protects published base/target
references. Nothing is discarded, retired or cleaned up on any path.

Before D8.1 construction both persisted generation identities are compared with
the request's exact bytes/digests. This read is identity evidence, not D6's full
metadata, source or durability authorization. No duplicated execution checks or
new execution capability is introduced. Base current must match exactly; only
an already selected target of the same activation identity can enter retry.
Its digest must then match canonical construction. No implicit rebase occurs.

## Results and errors

Success returns one activation ID/digest, D4 publication disposition and D7's
fresh complete result. That same identity is passed to both D6 and D7. Optional
expected digest is independent caller evidence checked before D4.

`OperationalActivationError` retains stage, failure category, canonical identity
when available, and original exception via `exception_ptr` (including cause,
errno and primitive namespace outcome). Categories are intentionally conservative:

- `BeforeSelection`: an authoritative initial current observation excludes the
  requested target selection and this invocation has not entered D6. D4 may have
  left durable/uncertain residue. An inspection failure never grants this category.
- `SelectionUncertain`: initial authority/selection inspection could not establish
  the current state, or D6 was entered without returning successful target
  selection. This includes errors that individually report NotMutated; those do
  not prove the complete request history. No D7, rollback or discard follows.
- `AfterSelection`: D6 confirmed target selection, or an existing matching-ID
  target was observed during retry. In the latter case visibility alone does not
  establish durability; successful retry still runs D6 to repair barriers.
  D7 errors preserve selected target and all references.

No global terminal state is written. Repeat the same request and digest for
explicit retry. Corrupt/incomplete preparations can still block retries; the
coordinator never invents repair/cleanup authority. Concurrent external mutation
is outside the primitive contract.

## Validation scope

The new nonprivileged test uses empty persisted memberships to exercise bootstrap,
selected-base transition, identity rejection before publication, D4 failure,
published-but-unselected plan, pre/post-rename D6 faults, D7 barrier failure,
exact retry, base conflict, digest/witness rejection and D7 refusal of an
unselected plan. Calls use an already held State, with a 30-second CTest timeout
so recursive acquisition cannot silently hang the suite. Nonempty payload and
physical witness execution remain covered by existing D6/D7 qualification;
privileged scanner/mount tests are excluded on the Gentoo MSI. No physical
power-loss durability claim is made.

## Final-review correction

Initial classification now starts at SelectionUncertain. Only a successful
`inspect_selection` observation permits BeforeSelection for a request whose
ID/target is not selected. Observed retry targets retain AfterSelection; D6
still repairs their barriers before D7. No primitive, lock, identity, digest,
rollback or cleanup behavior changed.

The reproducible regression performs the real current rename, injects EIO after
it, then injects EIO through the existing ProjectionIo stat seam at the next
invocation's initial current observation. Both the same request and an alternative
request fail at Identity with SelectionUncertain. Projection namespace mutation callbacks are
counted; none runs, the alternative plan is absent, and exact original CurrentV1
(target, activation ID, digest) remains selected. A fresh retry succeeds with the
original identity. A subsequent confirmed retry barrier failure remains
AfterSelection with that same identity. D6/D7 faults now check exact CurrentV1;
rethrow_exception checks ExecutionError type, cause, outcome, errno and diagnostic,
and the expected-digest test checks SchemaError code and diagnostic. Existing
pre-D6 identity/construction/publication cases still assert BeforeSelection after
a successful initial observation. These remain empty-membership coordination
checks, not nonempty payload or power-loss qualification.

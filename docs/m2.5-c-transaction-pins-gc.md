# M2.5-C transaction pins and recoverable GC

## Scope and invariant

This phase changes artifact lifetime and garbage collection, not selection,
activation durability, transaction commitment, startup recovery, or historical
selection provenance. Artifact Schema v1, identities, generation/current codecs,
resolver/dependency semantics and trusted.* inspection remain unchanged.

For one bound store/generation authority, roots are the union of ArtifactIds in
all persisted generations and all valid registered pin manifests. A transaction
must durably pin an ID before publishing or adopting its authoritative payload.
A pin may name an absent payload. Lease ownership never filters roots. Invalid
or ambiguous root metadata aborts collection before its first detach.

All persisted generations, including historical and unselected generations,
remain roots. Publication is not installation commitment.

A legacy membership that resolves through a symlink into the bound ArtifactId
namespace also roots the corresponding object. This preserves legacy alias
activation without allowing collection to detach its payload.

## Authority binding

`AuthorityContext` takes the exact generation directory, not its state parent.
`GarbageCollector(AuthorityContext)` and its `GenerationDirectoryTag` constructor
use this exact directory. The old `(store, state_parent)` constructor remains an
explicit compatibility adapter to `state_parent/generations`.

Two matching internal schema-v1 binding records identify absolute, no-parent-
traversal store/generation locators:

* `objects/v1/sha256/.athena-transactions/authority.toml`
* `<generation-authority>/.athena-store-authority.toml`

Fields are `schema_version`, `store_authority`, and `generation_authority`.
No inode, device, PID or mount ID is persisted as an identity. Runtime mount and
inode checks remain necessary. One store cannot serve independently managed
generation authorities; one generation authority cannot bind another store.
Aliases that cannot establish the same strict locator binding are rejected.
The configured target continues to use this generation/store pair; this phase
introduces no target activation or selection record.

The generation-side witness prevents an absent store-local registry from being
interpreted as a fresh empty registry. Missing bindings/registered state require
reconciliation, not automatic erasure of roots. Initial binding setup holds
exclusive State followed by StoreGc. A partially established initial binding
can be completed only when the store registry contains its binding record alone,
with no registered transactions. This is initialization, not stale-transaction
reconciliation.

## Registry, manifests and leases

The registry is beneath the actual SHA-256 namespace, including when that
namespace is a nested supported mount:

```
objects/v1/sha256/.athena-transactions/
    authority.toml
    <32 lowercase random hex>/
        lease
        pin.toml
```

Administrative directories have exact 0700 modes and effective-UID ownership.
Files have exact 0600 modes, effective-UID ownership and one link. Reads are
bounded to 16 MiB, no-follow and descriptor-relative; mount and named-inode
identities are checked. Unexpected entries in registered directories fail closed.

Canonical pin format (fixed writer order, LF, trailing newline):

```toml
schema_version = 1
transaction_id = "0123456789abcdef0123456789abcdef"
artifacts = [
    "sha256:aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa",
]
```

Only these fields are accepted. Directory and record IDs must match. IDs use
exact ObjectStore lowercase SHA-256 grammar. Arrays are sorted, duplicates are
forbidden, and the parser compares against canonical serialization. Empty arrays
are valid. There is no expiry or committed/active state claim.

Transaction IDs use 128 getrandom bits, exclusive creation and collision retry.
`.prepare-<id>` names are disjoint from registered IDs and cannot publish objects.
Their leftover private preparation is nonauthoritative; no startup sweep is
introduced. Unknown registry names fail closed.

Registration prepares a lease and empty manifest privately, synchronizes both
files and the directory, acquires the rank-3 immutable-inode flock lease before
StoreGc, publishes NOREPLACE, and synchronizes the registry. Registered lease
contents are `<transaction-id>\n`. Pin additions hold StoreGc and use M2.5-A
complete-write/file-fsync/atomic-replace/parent-fsync semantics.

The owner never automatically retires on destruction. An update/publication or
handoff failure stops further owner operations conservatively. A failed update
before replacement leaves old pins intact; a failed barrier after replacement is
OUTCOME UNCERTAIN. A crashed update temporary inside registered state stops GC.

Valid pins survive clean owner exit, SIGKILL and an unlocked lease. A forked
inheritor can retain the flock open-file description. Exec closes foundation
fds. Lease probing is not abandonment; C never expires or reconciles stale pins.

## Publication and generation handoff

`ObjectStore::prepare` scans, materializes, finalizes, synchronizes and verifies
private output outside broad locks. `TransactionPins::publish` then takes
StoreGc, durably adds the ID, and invokes private authoritative publication.
NOREPLACE, existing-winner identity/model verification and synchronization retain
M2.5-B semantics. Publication uncertainty retains an already durable pin.

The explicitly named `*_unprotected_for_test` ObjectStore seams preserve focused
M2.5-B mechanics tests. Production transaction code never calls them. Normal
ObjectStore has no public ordinary publication or recursive-removal method.

`ExecutionOptions::transaction` supplies a caller-owned handle. Successful
standalone realization cannot silently drop protection; publication without that
handle fails. Modern installation owns the handle across builds, cleanup,
validation and generation creation. Inherited surviving realizations are pinned
under shared State then StoreGc before their source root could be discarded.

`GenerationManager::create_pinned` takes exclusive State then StoreGc, validates
the binding, pins/verifies realization references, allocates and durably
publishes unchanged generation metadata. Ordinary `create` rejects unchecked
realization records; the metadata-only fixture seam is explicitly unsafe and
named `create_unprotected_for_test`.

Handoff holds shared State then StoreGc, loads/validates the superseding
generation, checks coverage of every pin, re-establishes file/directory/parent
barriers, and retires the registry entry. Current selection is not a precondition.
Install/remove currently hand off after their existing switch succeeds so their
existing failure/discard flow retains transaction protection throughout.

Retirement atomically moves the transaction directory into
`.athena-retired-transactions/<id>` beneath the object namespace and synchronizes
both parents. The owner keeps its lease through durable retirement. Subsequent
administrative cleanup is private and best effort. Retirement uncertainty stops
the owner; no rollback or false restoration claim is made. Explicit `abandon`
is available only when no continuing recovery use exists; it is never destructor
policy.

Discard now holds exclusive State. Switch holds shared State to retain its
persisted source generations against discard; this does not make current writes
or activation durable and does not solve concurrent transaction selection.

## Locks and snapshots

The existing process-wide hierarchy remains:

```
TransactionLease (3) -> State (10) -> StoreGc (20)
```

Equal-rank nested acquisitions remain errors, including across threads and
inherited fork registries. `StoreGcLock` is a typed ownership proof for already-
locked pin additions. A GC child of a transaction owner must exec before using
new lock APIs; tests exercise this explicitly.

GC first establishes/validates binding, then takes shared State and exclusive
StoreGc. Each snapshot enumerates generations exactly once, derives both legacy
and ArtifactId roots, validates all transaction records and unions every pin.
Candidates are determined only after all roots validate.

One trash lease is claimed before authority locks. GC re-snapshots before each
detach and holds both locks through decision, rename and both barriers. This
avoids simultaneous rank-3 leases and avoids a stale released decision. It costs
additional root scans for many garbage objects; correctness takes priority.
Publication/adoption and pin mutation conflict on StoreGc; generation creation
and discard conflict on State. No StoreGc-to-State inversion or lease probe
inside authority locks is introduced.

## Recoverable deletion

Modern trash is beneath the actual object namespace:

```
objects/v1/sha256/.athena-gc-trash/<32 random hex>/
    lease
    <64 lowercase artifact digest>
```

Legacy trash is separately beneath the legacy store root, with `payload` as its
fixed detached payload name. Containers hold one object and a 0600 single-link
lease; administrative directories are 0700, no-follow and owner validated.
The independently versioned lease record is `athena-gc-trash-v1\n<id>\n`;
unknown/truncated versions fail validation. Private preparation, file/directory synchronization and NOREPLACE container
publication occur before authoritative detach. The rank-3 claim precedes State
and StoreGc. Competing reclaimers use nonblocking existing-only lease acquisition
and revalidate identity before use; they never create a missing lease.

Under authority locks, GC validates the source directory and same mount, renames
NOREPLACE to trash, fsyncs the authoritative source parent, then fsyncs the trash
container. Rename is logical deletion; both barriers establish durable detach.
Collision and EXDEV are errors. No copy/unlink fallback exists. A post-rename
barrier failure is OUTCOME UNCERTAIN: the pass stops and that container is not
recursively deleted.

After releasing authority locks, the claimed private walker uses openat2
RESOLVE_NO_XDEV/RESOLVE_NO_SYMLINKS, statx mount IDs, descriptor-relative
inspection/unlink, and inode/type revalidation. Same-device bind mounts are
rejected. Payload symlinks are unlinked without following them. Permission
restoration occurs only in private trash, never in the authoritative namespace.
An unprivileged cross-parent rename of a finalized read-only directory may fail
EACCES; that safe pre-rename failure is not bypassed by chmod or copying.

Changed directories are synchronized before their parents are removed. After
payload reclamation, the container is synchronized. Final lease/container
removal occurs under StoreGc while the claim fd remains open, then the trash root
is synchronized. Empty private containers left between final unlink/rmdir can
be safely completed under StoreGc. Missing leases with surviving payloads remain
ambiguous and fail closed.

`reclaim_trash` is explicit C machinery, not automatic startup recovery. It
claims a validated container before authority locks and re-establishes source and
container barriers before recursive deletion, including uncertain crash
leftovers. A modern payload that aliases an authoritative inode is rejected
before reclamation. Corrupt/ambiguous containers are conservatively left. Competing
completed reclamations are handled idempotently. `.prepare-*` remnants remain
private; this phase does not sweep abandoned preparation state.

## Legacy boundary

Any valid registered transaction blocks legacy sweeping as a whole, regardless
of lease liveness. Invalid root state aborts both collection domains. Legacy
installation registers before reusing/publishing legacy payloads. Modern mixed
installation/removal also retains this coarse guard. Semantic rejection remains
read-only before registration. Legacy payload identities, metadata formats and
partial legacy publication behavior are unchanged; this does not upgrade legacy
publication to M2.5-B durability.

Legacy collection now uses detach-before-recursion and the same mount-safe private
walker. A legacy-only symlink locator is explicitly bound to its real authority
at construction; modern ObjectStore never accepts linked authority locators.
Unsafe `.athena` ownership markers fail closed instead of following links.

## Filesystem and failure contract

All durable mutations retain ext-family/XFS/Btrfs support and honest local
rename/flock/fsync prerequisites. tmpfs only proves ordering/error behavior.
Overlayfs, NFS, arbitrary FUSE and unknown filesystem types remain unsupported.
Registry/trash share the actual object mount. Generation metadata may be on a
different supported persistent filesystem: handoff is ordered durability, not a
cross-filesystem atomic commit. Runtime mount IDs are not persisted.

The narrow per-operation syscall table adds mkdir/chmod for administrative
creation and private permission restoration. Existing write/fsync/rename/unlink
boundaries cover registration, updates, retirement, detach and cleanup. Production
uses immutable direct bindings; test callbacks are operation-local and obey
normal errno semantics. Primary persistence stage/errno/uncertainty survives
secondary ObjectStore cleanup errors. Failed trash cleanup reports failure with
identifiable private residue; durable detach is never reported as restoration.

C guarantees intact authoritative objects, conservative durable roots and
contained restartable trash. It intentionally permits stale-pin leaks pending F.
It does not supply transaction-intent reconciliation, automatic migration,
durable activation, selection commitment/history, or power-loss qualification.
SIGKILL tests prove process-death behavior only.

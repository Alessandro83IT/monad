# M2.2-B.1 public artifact contract

ADR-001 is authoritative. This prerequisite adds `AmbientSourceBuild` after the
existing origin values, with serialized spelling `ambient_source_build`.

| Origin | BuildInputId |
| --- | --- |
| BuiltFromAthenaIR | Required, nonempty; existing controlled IR semantics |
| AmbientSourceBuild | Absent; effective inputs are uncontrolled |
| ImportedBinary | Absent; producer attestations remain deferred |

A native build with a complete controlled build description would need an
appropriate controlled-origin contract; it must not use AmbientSourceBuild or
claim Athena IR provenance merely to attach an identity.

ArtifactMetadata retains its existing ArtifactId, output digest, manifest digest,
provenance and optional BuildInputId. IDs remain opaque, nonempty typed values.
Contract validation does not establish local verification or enforce a future
canonical artifact scheme on existing opaque metadata. The SHA-256/domain/schema
rules for newly realized identities still apply under ADR-001; their specification
and implementation are subsequent work. No identity is generated here.

Source candidates may reference IR or ambient artifacts; imported candidates may
reference only imported artifacts. ImportedBinaryMetadata.original_digest remains
a transport digest. Artifact identity stays in the separate ArtifactMetadata
payload, and no producer BuildInputId is inferred from the archive.

The existing version-1 TOML codec accepts the additive origin spelling. Existing
spellings, fields and meaning remain unchanged, including embedded snapshot
metadata. Older readers reject the new origin explicitly; no migration is needed
for existing documents. No hashing or verification behavior is added.

PackageSelection already associates selected candidate identity/provenance with
an optional artifact payload. InstallPlan remains pure and immutable. B.1 adds no
execution-result association or store locator: there is no public publication or
executor result to carry one yet. Immutable publication must later provide the
association from the selected CandidateIdentity to ArtifactMetadata and an
immutable store reference, separately from shared payload metadata. It must allow
multiple candidates per artifact and multiple artifacts per BuildInputId.

PathLayout.store names a root, not an object identity. Legacy internal store
name/version paths, package metadata and path-only manifests remain legacy data;
they are not ArtifactIds. No store addressing algorithm is added. GenerationEntry
remains package plus store_path. M2.2-C must introduce versioned artifact/output,
candidate/provenance and immutable reference associations with dual legacy/new
readers and reachability support, without synthesizing historical identities.

Next prerequisites are the versioned canonical artifact/normalization
specification (B.2), followed by supported scanning/hashing and verification,
immutable content-addressed publication, and concrete realization associations.
None of those behaviors is implemented by this contract change.

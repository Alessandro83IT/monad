# M2.5-D4 — Durable Activation Plan Persistence

Status: proposed specification; implementation requires separate authorization.
Baseline: `main`, `1ae556dacd4a052e7feb4bf13017818215976614`.
Normative MUST/MUST NOT requirements below describe D4, not existing behavior.

## Objective and non-objectives

D4 publishes one immutable, authority-bound pair of `ActivationIntent` and
`ActivationPlan`, and re-establishes its durability after interrupted attempts.
It uses the exact D1 codecs and `PlanDigest`. Atomic visibility of the complete
pair and successful durability barriers are separate postconditions.

D4 MUST NOT modify `generations/current`, projected entries, payloads, source
permissions, witnesses, work containers, adoptions, D1 codecs or terminal status
semantics. It does not execute operations, authorize generation 0, validate live
base selection, seal sources, introduce pins, integrate GC/discard, publish
statuses, orchestrate startup, or perform retention/cleanup. No mutable progress
record, readiness marker, self-digest field or new lock is introduced.

### Existing foundation versus proposed guarantees

* D1 already supplies strict canonical codecs, bounds, combined identity and
  old-witness/base namespace checks. Codec success grants no mutation authority.
* D2 already supplies the two-sided projection binding, retained authority fds,
  exclusive `ProjectionState`, constrained traversal and filesystem contract.
* D3 already distinguishes content identity, current-instance observations,
  barriers and authorization. Its recovery synchronizes newly opened instances.
* The baseline has no durable activation-plan namespace, publication or recovery.
  Its administration validator rejects `plans` and `.plans-bootstrap`.
* All D4 layout extensions, APIs, protocols and tests described here are proposed.
  No source implementation is included in this document.

## Three distinct boundaries

| Boundary | Successful result establishes | Does not establish |
| --- | --- | --- |
| Document inspection | Canonical pair, ID/digest, binding and stable observation during this read | Durable publication, retention or execution permission |
| Durable recovery | Expected pair's current instance and required namespace chain synchronized and revalidated | Live selection validity, source availability, ownership or permission to execute |
| Execution authorization | Reserved for D6/D7, using current selection, exact generation documents, sources and physical witnesses | Supplied by neither inspection nor recovery |

D4 does not read `current` or require referenced generations/sources to exist.
Their numbers, digests and references remain immutable claims to be checked by
later milestones. This permits inspecting/recovering the document needed to
diagnose missing references. Persistence MUST NOT be presented as executability.

## Planned internal C++ API

The intended module is `activation/plan_persistence.hpp/.cpp`; existing D1
`plan.hpp/.cpp` stays unchanged. Names below are proposed internal interfaces.

```cpp
struct PlanIdentity {
    ActivationId activation_id;
    PlanDigest digest;
};

struct InspectedActivationPlan {
    ActivationIntent intent;
    ActivationPlan plan;
    PlanDigest digest;
};

enum class PlanPublication { Published, AlreadyPublished };

struct PlanPersistenceResult {
    InspectedActivationPlan document;
    PlanPublication publication;
    ProjectionOutcome outcome;
};

ProjectionOutcome ensure_plan_namespace(
    ProjectionContext&, const ProjectionState&);

InspectedActivationPlan inspect_activation_plan(
    const ProjectionContext&, const ProjectionState&, const ActivationId&);

PlanPersistenceResult publish_activation_plan(
    ProjectionContext&, const ProjectionState&,
    const ActivationIntent&, const ActivationPlan&);

PlanPersistenceResult recover_activation_plan(
    ProjectionContext&, const ProjectionState&, const PlanIdentity& expected);
```

* `ensure_plan_namespace` is the explicit bootstrap/retry boundary. It never
  repairs a D2 binding or changes an existing incomplete `plans` namespace.
* `inspect_activation_plan` reads a published pair only, performs no fsync or
  initialization, and returns observations without a durability certificate.
* `publish_activation_plan` validates/serializes its independently supplied pair
  before any mutation, ensures the infrastructure, and publishes or resumes only
  exact complete state. Existing publications require equality of both bytes.
* `recover_activation_plan` requires a published pair and an independently
  expected ID/digest. It performs no mkdir, write, rename or cleanup. It cannot
  promote a preparation or bootstrap an absent namespace.

Missing state has a typed error, rather than an implicit initialization result.
The returned values are not unforgeable execution/durability capabilities. They
cannot carry barrier evidence across release of State or writer exclusion.
Durability-requiring subsequent uses MUST recover the current instance again.

The independent expected digest is a caller contract: it comes from the original
authorized request or a separately validated durable reference, such as a future
D6 current record. Hashing the candidate under recovery and passing that value
back as its own expectation does not satisfy this contract. Inspection remains
available for discovery; D4 does not decide which discovered plan to execute.

An internal `PlanAccess` boundary, analogous to `LegacyAccess`, may access retained
context fds and validate State. Callers MUST NOT supply filesystem/witness paths.
I/O callbacks are owned per operation/context, obey errno conventions, never
throw, and safely retain captures. Production callbacks MUST conform to the
requested I/O operation, including its actual effects, return value and errno;
they MUST NOT introduce unrelated namespace/content mutations. Reuse existing
`ProjectionIo`/`Syscalls` operations; add operation-local read/enumeration seams
where needed. No mutable
global production hooks or arbitrary fd exposure is permitted.

## Persistent layout and compatibility

```text
<projection-root>/.athena-activation/
    authority.toml
    witnesses/
    work/
    adoptions/                         # optional; unchanged D3
    .plans-bootstrap/                  # optional private bootstrap residue
        .preparations/                 # empty when bootstrap is reusable
    plans/                             # complete published infrastructure
        .preparations/
            <activation-id>/
                intent.toml
                plan.toml
        <activation-id>/
            intent.toml
            plan.toml
```

`.plans-bootstrap` is the prepared infrastructure itself, not a permanent
registry, lock, record or payload directory. Its name is consumed by publication.
There is at most one such slot. No random sibling temporary names are needed.
Incomplete preparation files/children in this illustration may be absent after
failure; they do not constitute published state.

All D4 directories MUST be real directories, effective-uid owned, exactly mode
0700 including absence of special bits, on the retained projection mount.
Documents MUST be effective-uid owned, exactly mode 0600 regular files with one
link. Existing unsafe entries MUST NOT be chmodded, chowned, followed or replaced.
No regular-document hard links are created. Modes remain mandatory under umask:
unexpected modes fail closed rather than changing foreign entries.

Application immutability means no D4 overwrite API; mode 0600 does not protect
against the effective owner. Equivalent-authority writers must remain excluded.
Runtime inode/device/mount IDs are never persisted.

The future D4 validator must add exactly `plans` and `.plans-bootstrap` to D2's
administrative grammar. This is a necessary additive layout extension, not a
claim that unmodified baseline binaries accept the layout. It MUST preserve all
D1 schemas, two-sided binding checks, D2 witness/work grammar, D3 adoption grammar,
metadata gates and no-follow/no-cross-mount contracts. Unknown admin entries
still reject; no generic temporary-name exception is allowed.

Global context validation recognizes a safe bootstrap slot as opaque private
residue: empty or containing only a safe `.preparations` directory. It does not
complete or publish that slot. A safe slot may coexist with `plans` for diagnosis;
bootstrap/publication/recovery then reject that ambiguous state. Existing D2/D3
operations confer no ownership or execution authority on either slot.

Published `plans` MUST contain a safe `.preparations` directory and canonical-ID
containers. Global namespace-shape validation by `ProjectionContext::revalidate()`
MUST check structure, entry names/types, owner, exact mode, mount identity and
administrative limits. Published containers MUST have exactly `intent.toml` and
`plan.toml`, with the required regular-file metadata; checking this shape MUST NOT
read or parse every published pair. Private preparation interiors are opaque at
global validation, as in D3, but their outer directory/name/mount and metadata
are checked. Targeted D4 reuse validates their exact interior.

Canonical parsing, combined digest, document IDs and document-to-authority binding
MUST be validated only for the pair targeted by a D4 operation. Global shape
success does not certify any pair's document validity. An unrelated pair with
malformed document bytes remains invalid and MUST reject when targeted; it MUST
NOT require parsing during each D2/D3 operation. Structural or metadata violations
still reject globally. Namespace validation performs no barriers, execution checks
or recursive call to context revalidation.

## Administrative limits

These are D4 operational limits; they do not change D1 document bounds.

| Quantity | Hard limit / required shape |
| --- | --- |
| D4 bootstrap slots | 1, fixed name `.plans-bootstrap` |
| Admin entries excluding only `.` and `..` | At most 6: three D2 entries plus optional `adoptions`, `plans`, `.plans-bootstrap` |
| Bootstrap entries excluding only `.` and `..` | At most 1, named `.preparations` |
| Reusable bootstrap `.preparations` entries | 0 |
| Published plus private activation containers | 4,096 combined |
| Entries in `plans` excluding only `.` and `..` | At most 4,097 including `.preparations` |
| Entries in `plans/.preparations` excluding only `.` and `..` | At most 4,096 |
| Entries in a targeted activation container | At most 2; exactly `intent.toml`, `plan.toml` for reuse/publication |
| Activation container name | Exactly 32 lowercase hex bytes, D1 grammar |
| Any enumerated component | At most 255 bytes; fixed-name/ID grammar checked before storage |
| Each canonical intent or plan document | D1 16 MiB, independently |
| Pair of document bytes | At most 32 MiB; no new 16 MiB pair limit |
| Sources/operations and document path bounds | Unchanged D1 limits |

Every enumeration skips only `.` and `..`, checks length/grammar and increments
its count before appending names or opening children. This rule applies to every
entry-count limit above, including empty and targeted-container inventories.
Dot-prefixed names are not exempt: `.plans-bootstrap` and `.preparations` MUST
be counted and validated in their respective parents. The first excess entry
raises `AdministrativeLimit`, without collecting the remainder. Combined
container accounting shares one operation-local budget across both parents;
duplicate IDs in the two locations are additionally a conflict. Enumeration
uses fresh directory open-file descriptions and checks readdir errors.

Global validation enumerates namespace shape and metadata without reading pair
contents. Deep validation retains only the targeted pair's document buffers and
decoded values; no API accumulates all published document bytes. The container-name
set is bounded by 4,096. The 4,097-entry `plans` limit includes its one mandatory
`.preparations` child; published and private containers still share the 4,096
budget, so their individual parent maxima cannot be added. The initial
implementation need not expose a configurable higher limit.

At capacity, exact published retry and preparation-to-publication rename remain
allowed because occupancy does not increase. New preparation creation MUST fail
before mkdir. Residues consume capacity; D4 never evicts them to admit a plan.
These finite limits bound work, not disk quotas or a power-loss guarantee.

## Formats, identity and authority binding

`intent.toml` is exactly `serialize(ActivationIntent)`; `plan.toml` is exactly
`serialize(ActivationPlan)`. Parsing uses the D1 functions with the expected
activation ID. Combined validation uses `digest_plan_documents` and therefore
preserves old-witness/base namespace validation.

```text
SHA256(
    "athena-activation-plan-v1\0"
    || u64be(intent_length) || canonical_intent
    || u64be(plan_length)   || canonical_plan
)
```

The domain's trailing NUL, length framing, order and canonical bytes are frozen.
Filename choice does not change the D1 digest. There is no digest file, status
field, target-current field or serialized runtime identity.

Every targeted operation MUST validate the held State token and context binding,
including both exact D2 records and the ObjectStore's exact authority. Intent's
generation/store/projection locator bytes and ProjectionId must equal that
binding, without canonicalizing or normalizing supplied bytes. Container name,
intent ID and plan ID must agree. Relevant named roots and private directories
must continue to name retained descriptors. Binding validation never initializes
or recovers a partial D2 binding.

### Evidence permitting reuse of a complete preparation

All of the following are required, not alternative checks:

1. Independently supplied expected intent/plan, successfully serialized and
   combined-validated before namespace mutation.
2. Exclusive State for the exact retained generation authority, complete D2
   binding, and equivalent-authority writer exclusion throughout the operation.
3. The preparation is at the internally derived canonical private path inside
   that binding, with valid protected ancestry, owner/mode/type and mount.
4. Exactly the two safe one-link regular documents; both bytes equal the expected
   serialization, not merely another pair with the same reported digest.
5. IDs, canonical parsing, authority fields and combined D1 digest all agree.
6. Retained descriptors and named-identity/content checks show a stable instance
   across reading, barriers, publication and final validation.
7. This invocation completes fresh barriers on those instances and their required
   namespace chain. Visible state never substitutes for a successful barrier.

This demonstrates authorized reuse under the trusted-namespace contract. It does
not cryptographically prove which process originally created the preparation.
SHA-256 is content identity, not a signature or authentication mechanism. The
effective owner can manufacture identical administrative bytes; resisting that
owner is outside D2/D3's exclusion contract. No authentication format is added.

## Locking and filesystem prerequisites

All four APIs require an already held exclusive `ProjectionState`. They never
acquire State recursively or introduce a plan/bootstrap lock. The order remains:

```text
TransactionLease, when present -> State -> StoreGc, when needed elsewhere
```

D4 document persistence does not acquire StoreGc. State excludes cooperating
GC snapshots/discard only during the operation, not after release. It is not a
filesystem snapshot and does not automatically exclude legacy/raw-store writers.
Such writers with equivalent authority must be quiescent. Privileged hostile
namespace/mount changes remain outside the supported contract.

Use descriptor-relative openat2 with RESOLVE_BENEATH, RESOLVE_NO_SYMLINKS,
RESOLVE_NO_MAGICLINKS and RESOLVE_NO_XDEV; directory opens include O_DIRECTORY,
O_NOFOLLOW and O_CLOEXEC. File reads additionally use O_NONBLOCK so FIFO rejection
cannot block first. statx must provide mount ID and required metadata; same-device
bind mounts are crossings. No weaker pathname/kernel fallback is allowed.

The inherited supported local filesystem contract is ext, XFS, Btrfs and tmpfs,
true atomic RENAME_NOREPLACE and honest file/directory barriers. Unsupported
filesystems must reject before D4 namespace mutation. Tmpfs qualifies ordering,
not reboot persistence. Authority roots and their preexisting outer ancestry
must already be trusted and durable. D4 creates no authority root or ancestor.

## Concurrency contract and observation boundaries

D4 adopts the existing D2/D3 model. Exclusive State MUST remain held throughout
all four operations, including their final validation and return. Other writers
with equivalent filesystem authority MUST remain quiescent throughout that
interval. State serializes cooperating Athena participants; it does not itself
exclude raw filesystem calls, legacy helpers that ignore State, or same-owner
external writers. Arranging their quiescence is a caller precondition. Production
I/O callbacks are trusted implementations of the requested operations, not
additional writers permitted to mutate unrelated objects during validation.
Privileged hostile namespace/mount writers remain outside the contract.

Under these preconditions, success MUST establish all existing binding,
document, namespace, current-instance and durability postconditions. D4 MUST
fail closed on substitutions or perturbations exposed by the prescribed
observations. Quiescence MUST NOT be used to omit named identity checks, mount
checks, exact binding/document comparisons, bounded inventories or barriers.
An observed discrepancy MUST prevent success even when writer exclusion was
supposed to hold. This contract provides no universal detection guarantee for
arbitrary modifications introduced after an object's last observation.

A sequence of separate reads/stats/enumerations cannot create an atomic snapshot
of all objects against arbitrary writers. Repeating a last check merely moves
its observation boundary. State and writer quiescence provide coherence across
those boundaries; metadata and digests do not replace that precondition.

## Invocation-local OperationEvidence

The implementation MUST maintain an internal `OperationEvidence` local to one
invocation and shared by bootstrap, preparation, publication, inspection and
recovery helpers as applicable. This is an implementation structure, not a new
public API, persistent record, lock, execution capability or global cache.
It MUST preserve:

* Authority anchors and necessary retained descriptors, including exact State,
  generation/store/projection authorities and protected named ancestry.
* Both D2 binding records' named and retained identities, required metadata and
  exact canonical contents compared with the authorized binding.
* The targeted documents' named and retained identities, required metadata,
  canonical bytes, decoded values and combined D1 digest. Recovery's independent
  expected digest remains separate from observations of the candidate.
* Bounded inventories and directory observations before/after enumeration,
  including structural observations of every foreign published container and
  its two document entries. Private preparation interiors remain opaque unless
  targeted; their names, outer metadata and mount identity remain mandatory.
* Named parent/child relationships before and after prescribed own transitions,
  including bootstrap rename and preparation-to-publication rename.
* Successful required barriers associated with the actual retained instances
  synchronized in this invocation, their phase and normative order.

The cumulative mutation/outcome ledger MUST remain separate from observation
storage. Replacing a phase's observation batch MUST NOT clear earlier mutations,
barrier failures or unresolved uncertainty. Barrier evidence MUST NOT be inferred
from a digest, visible state, another invocation or an identical replacement.

### Lifetime, phase identity and directory observations

Authority anchors, targeted instance identities, authorized binding contents,
expected target bytes/digest and barrier evidence MUST survive through the final
success decision or error. Descriptors needed to establish target/ancestry
current-instance durability MUST remain retained through final validation.
Each inventory batch MUST identify its logical phase and capture before/after
observations around enumeration using fresh directory descriptions. The batch,
including foreign structural observations, MUST remain available until that
phase's concluding validation completes; helper return MUST NOT discard it.

Own mutations MUST update only the expected affected relationships and inventory
transitions. They MUST NOT silently replace the authority or targeted instance
anchors, or accept unexpected changes elsewhere as a new baseline. A new batch
MUST be checked against those anchors and expected transitions before replacing
a prior batch. No phase may mix a pre-rename parent relation with a post-rename
barrier claim without recording and validating the transition.

Directory observations MUST include inode/device/mount identity, required type,
owner and mode, link count, size, mtime and ctime. Required statx fields MUST be
present; both timestamp seconds and nanoseconds MUST be compared. Actual
filesystem timestamp resolution can be coarser than its representation. These
metadata are auxiliary change observations, not a cryptographic inventory
identity or a guarantee that every mutation changes a timestamp. Exact bounded
structural inventories and named identities remain required. Metadata of a
parent MUST NOT substitute for observations of a child's interior or files.
A concluding structural pass MUST cover foreign published containers without
reading, parsing or digesting their document contents.

### Memory and descriptor budget

Structural evidence MUST be O(N) for N <= 4,096 combined containers, with at most
two document-entry observations per published container, bounded component names
and no foreign document buffers. Only the targeted pair may retain document
contents/decoded values under the existing independent 16 MiB bounds.

D4 MUST use a descriptor budget independent of N: the implementation MUST declare
and test a fixed bound for its additional simultaneously owned fds, counting
pinned target/binding/namespace fds, locator traversal temporaries and fresh
enumeration descriptions. Existing context/State fds and independently bounded
D2/D3 validation temporaries MUST be accounted for separately. A container count
of 4,096 MUST NOT require 4,096 simultaneously retained container descriptors.
Foreign observations may be stored as bounded name/metadata records and reopened
one container at a time from protected retained ancestry for concluding checks.
This relies on the exclusion contract and MUST NOT be described as pinning every
foreign inode against hostile replacement/reuse. The target and synchronized
namespace descriptors MUST NOT be released to satisfy this budget.

Tests MUST measure peak owned descriptors at small and full combined occupancy
and verify the declared bound, including failure paths and RAII release. Descriptor
exhaustion MUST fail with preserved errno and cumulative outcome; it MUST NOT
trigger weaker traversal, incomplete validation, cleanup, or a lower silently
substituted container limit. D4 MUST NOT raise process resource limits implicitly.

## Shared concluding protocol

All four APIs MUST use the same evidence/phase validation rules, with the data
and barrier requirements appropriate to the operation. The following structure
supplements, and does not reorder or replace, the ordered protocols below:

```text
validate independently supplied request where applicable
validate held State, exact authorities, binding and filesystem prerequisites
acquire anchors and bounded structural evidence; validate the targeted pair
for each prescribed bootstrap/preparation/publication/recovery phase:
    perform only its authorized own transitions; record mutations immediately
    for each required barrier in its existing normative order:
        arm cumulative phase uncertainty before barrier validation
        check relevant named/retained identities and mandatory metadata
        fsync the retained instance; record successful barrier evidence
        check the relevant identities and metadata again
    conclude the phase under continuing State and writer quiescence:
        collect a bounded structural batch, retaining foreign observations
        check before/after enumeration observations and expected transitions
        reread both actually named D2 records and compare exact binding contents
        reread target bytes when required; validate canonical pair and digest
        compare all applicable observations with authorized/retained anchors
        verify current named ancestry, inventories and source/destination facts
        verify the required barriers belong to those instances and this phase
        resolve only this phase's uncertainty after all checks succeed
return only after the invocation's applicable concluding checks succeed
```

Inspection uses the concluding checks with no mutations or barriers. Bootstrap
has no target documents. Recovery and published retry MUST compare post-barrier
target bytes/digest against the independently authorized expectation. Preparation
and publication MUST preserve exact request-byte equality and validate their
respective pre/post-rename relationships. A digest recomputed solely from old
decoded objects MUST NOT stand in for the required post-barrier document reads.
Named checks MUST start from current authority locators and retained protected
ancestry, not exclusively from retired parent descriptors.

The concluding checks MUST be finite, nonrecursive and shared; namespace-shape
validation MUST NOT recursively invoke context or concluding validation.
Implementations MUST specify their observation order and phase boundaries and
avoid redundant complete scans per individual helper/check. At most one complete
D4 structural batch per concluding validation is needed; the selected foreign
observations can be compared by bounded sequential reopens without another
complete global enumeration. Enumeration of individual recorded containers for
exact shape remains permitted and required where applicable.

Any failed required check MUST prevent success, preserve residue, retain its
typed cause/errno and use the separate cumulative ledger. Binding disagreement
is AuthorityMismatch; observed instance/inventory change is Substituted; unsafe
or incomplete structure uses the applicable existing cause; barrier failure is
Durability. Starting a required barrier phase makes failures OutcomeUncertain
as already specified. Finite concluding validation establishes the normative
postconditions under writer quiescence; it does not promise universal detection
of a modification after that object's last observation.

## Bootstrap protocol

### Why publish the entire infrastructure

Sequential mkdir of `plans` then `plans/.preparations` can expose incomplete
public infrastructure. Instead prepare `.plans-bootstrap/.preparations` wholly
inside the reserved admin root, then rename `.plans-bootstrap` to `plans`.
No temporary entry is placed in an ordinary payload, witness/work or adoption
directory. A same-parent rename needs no additional permanent staging parent.

The reserved bootstrap-name exception above is the minimum D2 validator extension
needed to retain pre-publication residue. It is explicit, bounded and does not
weaken handling of arbitrary unexpected state. Reusing witness/work containers
or placing arbitrary random directories under admin would violate their grammar.

### State table

| `plans` | `.plans-bootstrap` | Explicit ensure behavior |
| --- | --- | --- |
| Absent | Absent | Prepare and publish fresh infrastructure |
| Absent | Complete exact empty infrastructure | Validate, resynchronize and publish that instance |
| Absent | Empty/incomplete/unsafe bootstrap | Conflict; preserve; never fill missing children on retry |
| Complete safe infrastructure | Absent | Resynchronize current infrastructure; no rename |
| Incomplete/unsafe infrastructure | Any | Conflict; never repair |
| Present | Present | Conflict; preserve both, even if apparently identical |

Recognizing a complete empty bootstrap is infrastructure reuse inside an already
bound trusted namespace; it proves no plan ownership and has no content digest.
Metadata, exact shape, State, binding, writer exclusion and current-instance
barriers are all required. Owner/mode alone are insufficient.

### Ordered protocol

1. Validate State, D2 binding, supported filesystem, shape and budgets. Retain
   admin/root descriptors; require both public destination and bootstrap absent
   for fresh creation.
2. Exclusively mkdir `.plans-bootstrap` mode 0700 and pin it. Exclusively mkdir
   its `.preparations` mode 0700 and pin it. No documents are written.
3. Require exactly that child and an empty child inventory. Synchronize in order:
   `.preparations`, `.plans-bootstrap`, admin, projection root. Validate identities
   and metadata before/after each barrier and final shape after this sequence.
   A complete recovered bootstrap follows this same sequence on current fds.
4. Revalidate binding, bootstrap/child and retained parent identities immediately
   before `renameat2(admin, ".plans-bootstrap", admin, "plans", RENAME_NOREPLACE)`.
5. After successful rename, synchronize in order: retained `.preparations`, retained
   published `plans`, admin, projection root. Verify `admin/plans` names the pinned
   bootstrap inode, the child is unchanged, and the source name is absent.
6. Return MutatedDurably. Existing complete infrastructure follows step 5's
   sequence on newly opened instances and returns NotMutated.

Source and destination rename parents in step 4 are the same retained admin inode.
The admin barrier in step 5 covers BOTH sides; one successful fsync suffices for
this aliasing, verified by runtime identity. This does not justify omitting a
parent barrier when publishing a plan between distinct parents.

An EEXIST winner is not accepted merely because its tree looks empty. Under State
the race is unexpected: report BootstrapConflict, retain the prepared slot, and
do not overwrite, remove it or automatically converge. A new invocation diagnoses
both locations. Unsupported NOREPLACE never falls back to replace.

Atomic bootstrap removes the public missing-child window during normal execution;
it cannot eliminate private mkdir residue or claim crash atomicity before barriers.
After failure/crash, incomplete observed infrastructure still fails closed. D4
provides no repair/cleanup for incomplete bootstrap; explicit D9 policy is needed.

## Plan preparation and publication protocol

1. Serialize expected intent/plan, derive D1 digest and validate binding fields
   before any bootstrap or plan mutation. Validate State and context.
2. Ensure infrastructure by the protocol above. Validate both ID locations and
   budgets. Existing publication plus preparation is a PreparationConflict.
3. An existing publication with no preparation must equal both expected documents.
   Run the durable recovery sequence below and return AlreadyPublished. Different
   canonical bytes are PublicationConflict; unsafe/malformed state is not a retry.
4. For absent state, reserve container budget before exclusive mkdir of
   `.preparations/<id>`. Pin the container. Exclusively create intent.toml, perform
   complete write then fsync; repeat for plan.toml. Retain both file descriptors.
   A syscall success creating/writing any private state counts as mutation.
5. An existing private container is reusable only under all seven evidence checks
   above. Missing, partial, empty or invalid documents are conflicts, never
   overwritten or completed. Newly written state receives the same checks.
6. Reread/validate both pinned documents and exact container inventory. Complete
   the preparation barrier sequence in order: intent file, plan file, container,
   `.preparations`, `plans`, admin, projection root. Initial writes' file barriers
   in step 4 do not replace this common fresh/reused preparation sequence.
7. Revalidate binding, named descriptors, document observations, bytes/digest,
   inventory and destination absence immediately before publication.
8. Rename the whole directory with
   `renameat2(preparations, id, plans, id, RENAME_NOREPLACE)`.
9. Complete in order: published container, `plans`, `.preparations`, admin,
   projection root. Here `plans` and `.preparations` are distinct rename parents;
   both MUST be synchronized, destination before source.
10. Validate destination-to-pinned-container identity, both document identities and
    bytes/digest, source-name absence, private metadata and binding. Return
    Published / MutatedDurably only after all required checks and barriers succeed.

Step 8 is the pair's visibility linearization point, not its durability point.
Documents are never renamed separately. No post-mutation rollback, unlink,
recursive cleanup or fallback overwrite is permitted.

RENAME_NOREPLACE EEXIST does not itself prove an idempotent publication. Report
PublicationConflict; preserve the winner and preparation. The operation must not
borrow the generic publish-tree helper's AlreadyExists behavior without D4's
independent pair/identity checks. A later invocation rejects simultaneous state.

## Durable published recovery

Recovery MUST verify expected ID/digest against a canonical published pair before
barriers. It checks private shape, bound intent fields, metadata, mount identity,
both ID locations, and absence of bootstrap ambiguity. Missing publication is
MissingPlan even if a complete preparation exists. No namespace is initialized.

Retain both document fds and container/parent/root fds through final validation.
The exact recovery order is:

```text
intent.toml current file inode
plan.toml current file inode
published container
plans                         # destination rename parent
plans/.preparations            # source rename parent, even when source is absent
.athena-activation
projection root
```

Each line denotes a successful fsync plus before/after identity/metadata checks.
Reread the pair and verify the independent expected digest after the sequence;
revalidate named ancestry, binding, exact inventory and source-name absence.
Any failed barrier/check prevents successful recovery. Never infer durability
from visibility, prior success, another process's cache, or a retired inode.

Successful recovery returns AlreadyPublished / NotMutated: this invocation made
no namespace/content mutation, although it established durability by I/O. It
does not infer whether the interrupted original operation ever returned success.

## Inode substitution and security invariants

Runtime identity is inode plus device plus mount ID, with pinned descriptors to
prevent reuse while checked. Mandatory file observations also include type, uid,
mode, nlink, size, mtime and ctime; statx must report required fields. Check
bounded reads for size/EOF consistency, in-place changes and named substitution.
Document bytes must still match after barriers. Timestamps are observations,
never persisted semantic identity or sole proof of stability.

* Substitution of authority roots against the retained context/token rejects;
  open a fresh valid context/token only through the existing D2 contract.
* Observed substitution of files, containers, `.preparations`, plans, bootstrap
  or admin during an operation rejects, even for identical bytes and safe replacement
  metadata. A synchronized retired inode cannot certify its replacement.
* A fresh operation may accept an already replaced identical instance only after
  all namespace/expected-content checks and fresh complete barriers on its fds.
  No persisted inode blacklist or inherited barrier proof is used.
* Content or binding changes fail expected comparisons. Symlinks, cross-mount
  entries, foreign owner/mode and multi-link document files reject.
* A validate-then-rename check cannot make POSIX conditional on the checked inode.
  Equivalent-authority writer exclusion remains mandatory; injected substitution
  tests check fail-closed observations, not resistance to hostile privileged races.
* Unknown and incomplete state is preserved. No state, including empty private
  directories, authorizes deletion or ordinary payload mutation.

## Errors and mutation outcomes

```cpp
enum class PlanPersistenceCause {
    InvalidDocument, IdentityMismatch, AuthorityMismatch, UnsafeEntry,
    AdministrativeLimit, BootstrapConflict, NamespaceIncomplete,
    PreparationConflict, PublicationConflict, MissingPlan, Substituted,
    UnsupportedFilesystem, Io, Durability
};

struct PlanPersistenceError : std::runtime_error {
    PlanPersistenceCause cause;
    ProjectionOutcome outcome;
    int error;                         // captured errno, or 0 when inapplicable
    std::exception_ptr underlying;     // retain D1/D2/persistence diagnostics
};
```

Invalid canonical syntax/schema/bounds is InvalidDocument with the D1 category
preserved. A canonical pair with the wrong requested digest/ID is IdentityMismatch;
an existing canonical pair differing from publish's expected bytes is
PublicationConflict. Missing/incomplete private pair is PreparationConflict.
Missing `.preparations` in published infrastructure is NamespaceIncomplete.
Unsafe metadata/type is UnsafeEntry; an observed named-instance change is
Substituted. Binding/token mismatch is AuthorityMismatch. Failed required fsync
is Durability with errno preserved. Causes and outcomes are independent.

Outcome accounting covers ALL D4 mutations in the invocation, including bootstrap
and private file creation/writes, not just the final rename. The implementation
MUST retain cumulative mutation state through bootstrap, preparation, publication
and recovery, recording earlier mutations, their completed durability/final checks
and any outstanding uncertainty. Every helper result or error MUST be combined
with that invocation state; a helper's NotMutated or local success MUST NOT erase
earlier mutations or uncertainties. Only successful required barriers and final
validation covering the affected state can resolve its uncertainty. No destructor
performs mutations.

A failure before the first mutation and before any required barrier phase is
NotMutated. After durable bootstrap, a failure before the next mutation/barrier
phase is MutatedDurably, even if that helper itself made no mutation. After private
mkdir, file creation or writing without the full required synchronization and
final validation, failure is OutcomeUncertain, even when bootstrap was durable.

| Outcome | Normative meaning |
| --- | --- |
| NotMutated | No namespace/content mutation by this invocation. Successful exact ensure/recovery may perform fsync. Pre-barrier validation errors with no earlier mutation also use this outcome. |
| MutatedDurably | Successful invocation changed D4 namespace/content and completed every required barrier and final validation. For an error, usable only when earlier completed helper mutations remain fully verified/durable and the later failure occurred before starting another mutation/barrier phase. |
| OutcomeUncertain | Any required barrier fails; or a mutating/preparation phase fails after mutation without its full successful barriers/final checks; or recovery/barrier-phase validation loses identity. No success or rollback is implied. |

Starting the first required barrier arms conservative uncertainty for errors in
that phase, including recovery that performs no namespace mutation. Successful
completion disarms that phase's uncertainty only after final validation; it cannot
clear outstanding uncertainty from an earlier phase. Thus successful standalone
recovery is NotMutated, but failed recovery barriers are OutcomeUncertain. A
successful recovery helper after durable bootstrap leaves the invocation
MutatedDurably. Causes remain
typed; uncertainty does not conceal EEXIST, ENOSPC, EIO or schema diagnostics.

| Example | Cause / outcome |
| --- | --- |
| Invalid input before bootstrap | InvalidDocument / NotMutated |
| Initial exclusive mkdir fails, no earlier mutation/barrier | Io / NotMutated |
| Bootstrap succeeds; capacity check then rejects before new phase | AdministrativeLimit / MutatedDurably |
| Durable bootstrap; exclusive private mkdir fails before any new mutation/barrier phase | Io / MutatedDurably |
| Durable bootstrap; private mkdir succeeds, document creation fails before full preparation synchronization | Io / OutcomeUncertain |
| Partial file write after create | Io / OutcomeUncertain |
| Rename conflict after preparation barriers | PublicationConflict / OutcomeUncertain (conservative publication phase) |
| First post-rename parent fsync fails | Durability / OutcomeUncertain |
| Independent expected digest mismatch before recovery barriers | IdentityMismatch / NotMutated |
| Any published recovery fsync fails | Durability / OutcomeUncertain |
| Identical file/parent replacement during recovery | Substituted / OutcomeUncertain |
| Successful exact published retry, no earlier mutation | AlreadyPublished / NotMutated |
| Successful bootstrap followed by new plan publication | Published / MutatedDurably, including both phases |

No result claims mutation absence for a file it created or wrote. Publication
disposition answers whether this invocation renamed the pair; mutation outcome
also accounts for infrastructure. Errors retain actual residue for inspection.

## Boundaries with D5–D10

| Milestone | Required interface / responsibility; not implemented by D4 |
| --- | --- |
| D5 GC/discard | Consume validated plan references under existing locking. Define roots for published plans, complete private preparations and incomplete residue; malformed state must not imply an empty root set. Protect referenced generations/sources after State release. |
| D6 selection commit | Supply independent expected identity; recover durability before commitment; compare exact live base/current and target document identities; authorize absent/generation 0; derive CurrentV1 using unchanged D1 ID/digest. |
| D7 reconciliation | Authorize execution separately; verify source membership/availability, fresh D3 seals, complete projection and physical witness ownership. Reopen/recover at a new exclusion boundary. Never mutate the immutable pair to record progress. |
| D8 command/handoff integration | Orchestrate APIs, independent expectations, writer exclusion and lock lifetime. Define handoff obligations without treating plan persistence as pin retirement. |

Terminal status remains only complete/aborted under D1. D4 creates/accepts no
`status.toml` inside a plan container and changes no status codec. A future layout
extension must be separately specified. D4 is internal until retention and
execution orchestration prerequisites are satisfied; it must not be wired into
the live switch path as part of this milestone.

## Test matrix

All tests are proposed, not executed by this documentation change. Checks must
remain active in Debug AND Release (`require`/exceptions, not disabled assert).
Callbacks are operation-local. Correctness synchronization uses pipes/events and
fresh exec, never sleeps. Every failure case checks actual filesystem facts,
typed cause/errno/outcome and preservation of unrelated state.

### Test models and reporting

Every test MUST declare one of these models before interpreting its result:

* **N — normative execution:** State and writer exclusion hold throughout;
  production-conforming I/O or explicit syscall failure/short-I/O simulation.
  Mandatory checks, ordered barriers, typed errors, outcomes and residue apply.
* **P — controlled perturbation:** a test injects a specified substitution,
  content/metadata change or inventory insertion, then becomes quiescent before
  the prescribed later observation/concluding validation of the affected state.
  This tests fail-closed observation and evidence lifetime. The test MUST identify
  the injection point and subsequent observation that must expose the change;
  persistent discrepancies MUST reject with the specified cause/errno/outcome.
* **A — adversarial diagnostic:** arbitrary mutations continue through the last
  callback, occur after the affected object's last observation, or falsify I/O
  observations. Such executions violate the normative exclusion/provider model.
  Record detected versus undetected changes and actual returned outcomes. An
  undetected change MUST NOT be reported automatically as a passed regression,
  a normative conformance success, or proof of current-instance durability.
  Universal A-model detection is not a D4 acceptance requirement.

Absence of an exposing observation MUST NOT silently turn a required P regression
into a pass. Its schedule must be made explicit: either supply the documented
quiescent concluding interval or label that particular execution A and preserve
it as a diagnostic. Existing regression cases MUST be retained, with their
injection/observation meaning documented; this change authorizes no test edits
or removal and claims no new test execution. A test-local mutation notification
may support an A diagnostic, but MUST NOT substitute for filesystem evidence or
be presented as a production guarantee. No mutable global hooks are introduced.

additional arbitrary last-callback variant is A and reported separately.

### Meaning of retained callback regressions

The original replacement of `plans` during the final `plan.toml` reread after
recovery fsync seven is P when the replacement persists through the subsequent
named-chain checks. Late bootstrap replacements of `plans`, `.preparations` and
admin are P when followed by those checks; a fresh valid invocation must establish
barriers on current instances. Binding changes during final document rereads or
admin `open(".")` are P when followed by rereading both actual named D2 records.
EOF insertions in the target container, `plans` and `.preparations` are P when
followed by directory observations and quiescent exact structural validation.
These cases remain required, with cause, errno, cumulative outcome, residue and
unrelated-state assertions.

Changes during concluding binding callbacks, including changes to a foreign
published container, are P only where a documented subsequent quiescent check
covers the affected content/structure. Required foreign-container regressions
MUST exercise preserved evidence and concluding structural checks. Mutations of
previously checked documents/bindings during the last directory or named-chain
callback, with no subsequent exposing observation, are A diagnostics. Preserve
these reproductions and report their actual limits; do not claim that additional
finite rereads guarantee detection of every possible final callback mutation.

Fault tests must first inventory successful fresh/bootstrap/reused/published
paths' syscall and fsync boundaries, then fail each boundary in a fresh fixture.
Record real descriptor identity and namespace facts rather than only call counts.
Failing retries are repeated before a fresh successful retry, ensuring no hidden
process-local proof/cache authorizes reuse. Include failures after a real rename
but before its wrapper returns, to exercise uncertain mutation observations.

SIGKILL tests must avoid inherited State open-file-description authority: release
parent locks before starting workers, acquire independently, and exec fresh
inspect/retry workers. Timeouts bound test failures, not synchronization semantics.
Debug and Release run the same behavior checks. Privileged tests have a separate
qualification result; return 77 means skipped, never passed. No scanner capability
bypass, global hook or weakening of D1–D3 tests is permitted.

## Verifiable acceptance criteria

1. D4 exists only as internal persistence primitives; forbidden live/payload/status
   effects remain absent and are verified by T16 snapshots.
2. Exact D1 serialization and digest vectors remain unchanged; no new document
   fields or codec modifications are needed (T01–T02).
3. Fresh bootstrap publishes a complete infrastructure using one same-parent
   NOREPLACE rename; incomplete/private residue never grants plan authority;
   both logical rename parents and root chain have verified barriers (T04–T05).
4. Published pair visibility is atomic via one directory rename, with explicit
   destination AND source parent barriers (T06, T09).
5. Reuse requires all seven provenance conditions. Inspection, durable recovery
   and execution authorization remain distinct; independent digest mandatory for
   recovery, no discovered preparation automatically promoted (T07–T08, T15).
6. Admin limits are enforced while enumerating, including combined capacity and
   early stop; D1 limits remain independent (T02–T03).
7. Current-instance substitution cannot borrow retired-inode barriers. Every
   required barrier failure prevents durable success and preserves evidence;
   no mutation is mislabeled clean (T09–T12).
8. State is exclusive and externally supplied; no new lock or recursive acquisition;
   TransactionLease -> State -> StoreGc order and independent-process behavior
   remain valid (T14, T16).
9. All required nonprivileged N/P matrix cases and existing applicable regressions
   pass in Debug/Release under their declared observation schedules. Retained A
   diagnostics report actual detection limits separately, never as automatic
   passes. Privileged cases are explicitly qualified or reported skipped;
   a skip never satisfies privileged qualification (T17).
10. No test or documentation claims physical crash/power-loss guarantees from
    process-death/fault-injection mechanics (T13, T18).

## Decisions and remaining boundaries

This specification selects fixed-slot atomic bootstrap, exact-pair preparation
reuse, 4,096 combined administrative capacity, independently expected published
recovery and conservative error uncertainty. It deliberately preserves incomplete
residue instead of inventing completion or deletion authority. Those choices
resolve the D4 design questions; they require approval of this specification
before implementation.

The concurrency and observation contract above is normative. Implementing the
shared evidence model and its measured descriptor bound requires separate approval;
this specification update does not authorize source or test changes.
D5's retention treatment of private/incomplete state, D6/D8's independent-reference
and execution orchestration, D9's status placement/cleanup and D10's storage
qualification remain explicit later-milestone decisions. Baseline binaries cannot
consume the extended namespace; release/downgrade handling belongs to command
integration and must not be silently inferred from this document.

# M2.5-D8-B4 — internal install/remove integration

Baseline: `c0a8b12528c979fbaba1be86d36629c3122c20c2`, branch `main`.
This document describes `src/activation/package_operation.*`. Qualification and
remaining physical prerequisites are recorded separately. This is an internal
adapter over completed, explicitly published targets; it does not dispatch CLI
commands, acquire sources, invoke builds, select repositories from disk, or
initialize a projection. No B5/B6 or legacy/GenerationManager change is included.

## Existing contracts and missing guarantee

The public `core::InstallRequest`/`core::plan_install` path resolves immutable
repository snapshots. `repository::adapt_snapshots` retains CandidateIdentity,
repository revision, snapshot reference and provenance. The private dependency AST
keeps package, capability, feature, version comparison, boolean/conditional/scoped
expressions, dependency roles and Host/Build/Target contexts distinct. B4 calls
this resolver, not a new graph walker, name-only provider matcher or repository
refresh. The older `install::InstallPlan` containing Package values is not the
identity-preserving public `core::InstallPlan` and is not substituted for it.

`installed::prepare_install`, `from_selection`, `inherit_profile_features` and
`validate_environment` already validate the complete preserved environment,
negative constraints, policies and provider consistency. Unsupported historical
semantics fail closed; B4 does not invent dependencies for old records.
`build_removal_generation` filters both legacy and realization memberships and
preserves policies. Its result still needs environment validation.

C.4 `realization::realize` returns records only after complete acquisition,
verification, extraction/build/staging, ArtifactId derivation and transaction-pinned
publication. Earlier objects can survive a later failure, but a partial returned
closure is not an install result. Its current supported recipe/transport subset
is unchanged. B4 accepts completed records from that trusted producer or existing
verified records, not download paths or build directories. Content identity does
not attest which producer ran: no new build attestation is claimed or invented.
Repository artifact identity/origin/BuildInputId, when declared, must match.

Existing `GenerationManager::create_pinned` verifies realization objects and
publishes immutable metadata without selecting it. Existing publication owns ID
allocation, collisions, barriers and transaction handoff. B4 uses that upstream
producer; it never invokes manager methods while holding ProjectionState.

B1 freezes exact documents and inventories and revalidates original CurrentV1 or
an exact selected-target retry. B2 archives canonical envelopes against an
independent expected identity. Neither validates source ownership nor supplies a
GC root. B3 routes an explicit existing target through B1/D8.2/D4/fresh D6/D7.
D6/D7 already rescan and synchronize sources, validate membership and witness
ownership, reject stale selection and preserve conservative failure outcomes.

The missing B4 guarantee was lifetime between preparation/archive and activation.
TransactionPins retains ArtifactIds, not generation metadata. A live lease and
B2 record do not stop `discard`. An added B3 regression demonstrates that exact
physical metadata gap. This is not a defect in B3's conditional caller contract.

B4 closes the gap using existing D4 publication under the SAME exclusive State
before successful preparation returns. D4/D5 already retain both generations,
artifact and legacy sources. B4 adds no root format or authority and does not
change any D4–D8 API, encoding, authorization or historical B3 behavior. D4 may
publish a plan without selecting it; its existing API is explicitly separate
from D6. Activation still enters only through B3 -> B1 -> D8.2 -> idempotent D4 ->
fresh D6 -> fresh D7. Early D4 retention does not authorize any of those steps.

## APIs and model

`build_install_operation_target(base, target_id, request, completed_records)` is
pure with respect to generation/store mutation. It resolves the full request,
requires exactly one record for every selected CandidateIdentity (no duplicate,
foreign or incomplete closure), checks semantic metadata and declared artifact
identity/provenance, normalizes profiles using existing installed semantics, and
validates the complete resulting environment. Exact raw executor semantics and
their existing profile-normalized persisted form are accepted; arbitrary extra
semantic claims are rejected. Preserved members remain in the result.

`build_remove_operation_target(base, target_id, package_names)` constructs both
membership collections, rejects empty/duplicate/missing package identities,
retains policies/profile configuration and validates the complete remaining
environment. A capability or feature name is not interpreted as a removal
identity. Unsatisfied reverse dependencies fail; there is no implicit autoremove
or resolver search for replacement providers. No store object is deleted.
Both builders require a target ID above the original base, matching a new
monotonically allocated generation. Manager-assigned final IDs remain the
existing producer's responsibility; B4 preparation uses the returned actual ID.
The existing legacy semantic capture can read metadata; these builders do not
claim global filesystem purity for historical legacy membership.

`PackageOperationInput` wraps an explicit B3 GenerationOperationInput: original
SelectedBase/CurrentV1, ActivationId, binding, existing target ID, full base/target
source inventories including zero-link members, and predecessor witnesses.
Callers publish the candidate through the existing pinned generation producer
before entering B4's exclusive State scope. An absent/stale/substituted candidate
at B4 entry is refused, never reconstructed or implicitly rebased.

`prepare_install_operation` resolves the supplied immutable snapshots once,
extracts the exact selected records from the persisted target, builds the expected
complete generation and compares all memberships/policies against it. It cannot
accept a target that merely contains the named root but lacks its dependencies,
contains unrelated replacements, or drops preserved members.

`prepare_remove_operation` builds the exact requested removal against the frozen
base and compares the complete persisted target. Both prepare functions use B3
for authority-before-path checks, bounded no-follow exact document reads,
B1 detachment/digest and B1.3 current observation. They then validate target
semantics and verify actual source inventories: ObjectStore verification plus
ArtifactId scan for modern payloads; existing seal verification and manifest
projection for legacy sources. Derived parents and explicit empty artifact
directories are compared, not just a list of nonempty packages. B1 validates
full source membership/budgets and witness structure; ownership is still D6/D7's
fresh responsibility. Current-instance artifact synchronization reuses ObjectStore
mechanics and
barriers through the bound store ancestry. Both exact generation documents and
their directories/authority are synchronized and checked again before D4, rather
than inferring durability from past producer claims. Legacy verification retains
its existing synchronization contract. Operation-local durability syscall callbacks
are an internal test seam, never persisted authority. After revalidation, existing
D4 publication acquires retention. Legacy semantic capture uses the existing D8
document byte bound; source/seal
verification precedes interpreting that metadata. No current record or managed
link is changed by preparation.

`PreparedPackageOperation` owns immutable B3/B1 values and
`PackageOperationReference { kind, GenerationOperationReference }`. Kind is
independently retained caller intent, not a new serialized authority. Both kinds
have the same B3 Switch execution shape; neither gains rollback privilege.
B1 exact-envelope bytes remain the only request encoding. Original base,
ActivationId, documents, inventory, PlanIdentity and envelope digest are fixed.
As with B3, relabelling a valid independent reference changes no authorization;
intent labels are not reconstructed from archive candidates.

`persist_package_operation` first recovers/revalidates the exact existing D4
retention plan, then delegates to B3/B2. `recover_package_operation` validates kind
and Switch shape before B2 I/O, uses B2/B1.3, validates target semantics and the
independently expected D4 plan. It may repair archive/retention barriers but never
selects or reconciles, reconstructs a target or publishes missing retention.
`activate_package_operation` ALWAYS repeats this recovery, then delegates to B3
which repeats B2/B1 validation before the sole D8 path. There is no overload
accepting cached observations as authority, unarchived activation, or fallback.

## Ownership, locks, lifetime and failures

The caller provisions the existing durable private 0700/effective-owner B2 root,
dedicated to the configured binding, in trusted ancestry disjoint from operational
authorities. B4 neither creates/chmods this root nor treats it as GC reachability.
The independently retained input/reference is not learned by archive enumeration.
Retain original input/intent independently BEFORE preparation attempts; retain
operation.reference() independently BEFORE B2 persistence. A prepare failure may
already have durable D4 effects. Reusing its original ID/input is explicit retry,
not permission to discover intent from residue or silently generate a new ID.

Every B4 call requires exclusive ProjectionState after any TransactionLease and
before StoreGc, plus exclusion of equivalent-authority writers and mount changes.
B4 acquires StoreGc only for modern payload verification. Legacy seal verification
uses its existing locks. It never constructs TransactionPins, calls handoff or
reenters a manager under State. Repository/build/acquisition work is upstream.
No lock survives a B4 return beyond caller-held State; D4 references supply the
durable lifetime. Source verification is scoped to writer exclusion, not an
atomic snapshot against arbitrary hostile writers or an ABA proof.

Before B4 preparation succeeds, the upstream producer owns publication/pins and
must protect its work while producing the target. B4 promises no recovery of
arbitrarily discarded upstream metadata. At entry, presence, exact documents,
current and actual sources are checked. After successful preparation, cooperating
discard consults D4/D5 and refuses both generation roots; GC retains the complete
source closure across State release/restart, independently of B2. The D4 root is
verified before B2 persistence/recovery. No boolean 'lifetime established' replaces
that check. Corrupt/missing/unsafe retention blocks the request.

Install/remove/rollback contenders serialize on State. Two B4 preparations can
retain plans from the same base; only one activation can select from that exact
base. The loser remains stale and retained, with no rebase or automatic cleanup.
Existing rollback B3 checks remain unchanged. D4 may reference inactive generations
indefinitely; administrative limits fail closed. Retiring/abandoning plans is an
existing/future lifecycle concern, not an implicit B4 destructor or B5 work.

Colliding ActivationIds with different intent/digest are rejected by D4/B2 without
overwrite. Generation collisions/publication stay with the existing producer.
B4 never removes generations, records, plans, payloads or pins on exceptions.
D4 errors retain their cause/outcome, including partial preparation/publication;
B2 errors retain archive-local uncertainty; D8 errors retain stage, original
identity and BeforeSelection/SelectionUncertain/AfterSelection. A B2 error does not
prove that a previous activation never selected. Recovery may repair barriers
before a later validation failure. No globally read-only failure is promised.

## Qualification boundary

The new test executable uses a test-local ELF scanner interposition reading real
fixture bytes/types. Positive source authorization is SIMULATED with respect to
trusted xattrs, scanner metadata safety and privileged provenance. Payload files,
D2 link/witness inodes, D4/D5 references, State locks, B2 files, syscalls, GC metadata
reachability and fork/exec competitors are physical local witnesses.
A second executable compiles the same fixture WITHOUT interposition and probes
production-scanner B4 preparation. Missing hidden trusted.* inspection is SKIP,
with asserted absence of D4/archive/current mutation, never a positive physical
nonempty authorization claim. No sudo/mount/privileged test/OOM stress is used.
Fault injections model syscall failures, not power-loss or hardware durability.

## Btrfs retention compatibility correction

Nonprivileged Btrfs integration exposed an existing prerequisite failure in
`generation::publication::existing_ids_for_gc`: it required directory nlink=2,
while Btrfs reports nlink=1. This blocked TransactionPins binding before B4 entry.
The read-only GC enumeration now accepts nlink=1 ONLY on a positively identified
Btrfs filesystem and ONLY after a fresh no-follow interior scan rejects every
real child directory and rechecks directory identity/metadata/timestamps. Other
filesystems retain the historical nlink=2 rule; mode 0700/effective owner and
regular private 0600/single-link generation.toml requirements are unchanged.
Thus the leaf-directory invariant is preserved rather than dropping a safety
check. Unsafe or unstable roots still block the full GC decision before detach.
No GenerationManager method, D4–D8 API/format, writer exclusion or selection
semantics changes. A regression runs on both ordinary tmpfs and physical Btrfs.

## IMPLEMENTATO

Internal module: `src/activation/package_operation.hpp` and `.cpp`.
Architecture and exact contracts: `docs/m2.5-d8-b4-package-operations.md`.

- Complete install/remove generation builders reuse the snapshot resolver and
  installed semantic validation; no new package/capability/feature/version rules.
- Preparation accepts an explicit original operational base and a complete target
  already published by the existing pinned producer. It checks the complete
  semantic delta, exact documents, actual payload identity and full inventories.
  The adapter does not acquire/download/build or implicitly publish a different
  generation; the producer remains the existing executor/create_pinned path.
- Actual current-instance payload and generation barriers precede retention.
  Source/seal verification precedes bounded legacy semantic interpretation.
- Preparation publishes existing D4 retention before returning; it does not
  select/reconcile. This closes the B2-only lifetime gap with D4/D5, independently
  of B2 and without adding an authority or root format.
- B2/B3 persistence, independent expected references, recovery without execution,
  and activation solely through B3/B1/D8.2/D4/fresh D6/D7. Missing/corrupt/stale
  inputs never cause fallback, implicit rebase, new IDs or cached authorization.
- Remove preserves every unrequested member, rejects reverse-dependency breakage,
  retains policy/profile semantics and never deletes a store object.
- Btrfs GC discovery compatibility fix preserves the leaf-directory invariant:
  nlink=1 requires actual Btrfs plus no-follow child-directory exclusion and stable
  directory metadata. All other ownership/mode/file-link checks remain strict.

GenerationManager and legacy CLI/install/remove implementations are unchanged.
No B5/B6, new serialized envelope, new authorization, automatic recovery execution,
plan retirement, commit or publication to a remote service was introduced.

## TESTATO

The main driver uses a closed inventory of 407 source/document inputs and fresh
Debug/Release build directories. Commands, compiler/cache/compile database,
per-test JUnit, full CTest logs and source/binary digests are preserved. The exact
`artifact_scanner_test` stress case and privileged-labelled tests are excluded;
network and OOM stress are not executed. The final source set is checked again
at the end, rather than trusting initial hashes after implementation changes.

`package_operation_test` exercises real B1/B2/B3/D4/D5/D6/D7 control paths with an
explicit test-local scanner provider. It reads real fixture payload bytes/types
but does not certify scanner privilege-dependent metadata inspection. Coverage:

- Simple install, install with dependency closure, exact decorated generation
  bytes, detached inputs, archive roundtrip, independent digest, retry/replay.
- Simple remove and complete multi-package remove; reverse dependencies,
  preserved policies/features, package identities versus capability/feature
  selectors and version constraints. No implicit autoremove.
- Missing/conflicting packages, incomplete/duplicate/foreign realization records,
  missing semantics, incomplete source membership and projection inventory,
  unavailable/corrupt payload, stale original base and wrong binding/digest.
- Symlinked generation/archive paths, traversal paths, corrupt envelopes/documents,
  missing retention, payload mutation after preparation and same-byte generation
  directory substitution during durability barriers. Fresh authorization refuses
  changed sources; identical bytes do not certify the old inode's barriers.
- Retention before first activation survives State release; actual discard refuses
  the target and actual GC retains its closure. Two fork/exec B4 contenders have
  exactly one winner and a stale retained loser.
- B3 regression demonstrates that a live TransactionPins lease and archived request
  alone do not retain generation metadata. Both the gap and its B4 solution have
  physical metadata witnesses.
- GC protocol regression accepts valid leaf generation roots and rejects a real
  unexpected child directory on both tmpfs and Btrfs.

There are **66 B4 syscall fault cases**: 16 source/generation preparation barriers
(4 boundaries x before/after x install/remove); 4 early D4 publication cases;
28 B2 persistence cases (7 events x before/after x both kinds); 12 B2 recovery
barrier cases (3 events x before/after x both kinds); 6 D6/D7 selection/reconciliation
cases. They preserve the original request identity and use explicit retry. These
are syscall-error simulations, not crashes, disk faults or power-loss trials.
The unchanged full-suite B2/D4/GC SIGKILL regressions provide separate process
failure coverage; their outcomes are not promoted to hardware guarantees.

A supplemental consumer, `mixed-concurrency.cpp`, includes the SAME hashed test
fixture/provider and links against each final clean Debug/Release library. Its
source, compiler/run commands and logs are preserved separately from CMake's
inventory. It covers a complete zero-link realization install/remove, removal of
only the root while keeping a dependency and its KEEP witness, and four gated
fresh processes contending as B4 install, B4 remove, B3 rollback and GC. Exactly
one activation wins; two requests become stale, GC succeeds, and both pending
B4 plans/closures stay rooted independently of the winner. It also runs on Btrfs.

## Witness classification and physical preconditions

Physical local witnesses: generation/request bytes and digests; metadata inode
substitution; State/StoreGc/lease acquisition; D4/D5 references; B2 publication and
recovery residue; ordinary payload bytes; projection symlink/witness inodes;
cooperating discard/GC refusal; gated fork/exec contention; local tmpfs/Btrfs IO.

Simulated: successful scanner metadata authorization in the positive B4 tests;
completed-producer record/materialization fixtures; injected syscall failures.
Production uses the existing scanner, ObjectStore, executor and generation
producer, without those test providers. The test interposition is confined to
consumer executables and is not linked into libathena_core.

`package_operation_scanner_test` compiles the fixture WITHOUT scanner interposition.
On this unprivileged host, production source inspection cannot certify hidden
`trusted.*` xattrs: the positive physical case is SKIP. The refusal actually checks
that current, the request archive and the new D4 plan remain unchanged. No bypass
or weakened metadata policy was added to obtain a PASS.

## NON TESTATO

Positive physical nonempty B4 execution with the production scanner; privileged
legacy sealing/adoption/owner/mount configurations; arbitrary hostile writers or
mount changes; reboot/power-loss; producer attestation; OOM stress; network
acquisition; LeakSanitizer. Positive legacy-specific B4 seal integration is not
claimed from the simulated modern-payload cases. Existing lower-layer regressions
remain separate evidence. ASan/UBSan finite checks are not universal proofs.

## BLOCCATO DA PRECONDIZIONI

The production-scanner positive physical case requires complete trusted-xattr
inspection that this unprivileged session does not have. B4 refuses it before
retention/activation; no unsafe successful operation depends on assuming that
inspection succeeded. No sudo, mount or privileged test was used.

Durable private root provisioning, honest supported-filesystem barriers and
exclusion of equivalent-authority writers/mount changes remain explicit existing
caller/deployment contracts. B4 verifies the concrete documents/sources, actual
barriers and D4 retention; it does not infer these facts from a serialized token.
No unconditional recovery of arbitrarily discarded upstream producer work is
promised. D4 retention applies after successful B4 preparation, including before
B2 persistence. Failed preparations can retain conservative D4 residue.

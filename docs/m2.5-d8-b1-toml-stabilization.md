This report covers the authorized stabilization of H1-R1 and the shared TOML
frontend, including B1.1/D8.1/D8.2 integration. It does not implement B1.2/B1.3,

## Final architecture and audit corrections

The former three-header shadow overlay is replaced by a complete 51-header
toml++ 3.4.0 fork in `third_party/athena_toml`. All library namespaces, types,
friends, templates, inline definitions, macros and header guards are isolated
from upstream. `third_party` is a PRIVATE core include; no installed public
header mentions fork types. Existing config/package/manifest loaders keep the
original parser. Codecs that exchange internal AST values use the fork throughout.
The former `third_party/toml++` header files are removed/replaced.

HIGH ODR finding: addressed with complete namespace/macro/type separation,
reproducible source transformation, opposite-include-order compilation, a
public-only upstream consumer linked to athena_core, and object-symbol checks.
No claim is made of a mathematical proof covering arbitrary external macro
configurations, platforms, linkers or consumers.

MEDIUM legacy errors: `read_metadata(path)` and its bounded overload normalize
file/frontend errors to `std::runtime_error`, retaining the store path and
underlying diagnostic. A shared internal stream conversion boundary allows
deterministic short-read/growth regressions without racing writers. Tests cover
missing files, malformed TOML, frontend structure/type rejection, byte bounds,
incomplete reads, growth and permissive one-argument extension fields.

MEDIUM independent compatibility: separate upstream-original and guarded-Athena
executables compare acceptance and type/value fingerprints on 35 fixtures,
covering every frontend profile. Seven malformed cases must agree on grammar
rejection; three valid-TOML hostile cases intentionally fail typed structure or
identity checks. Every positive fixture also rejects a zero-node budget. The
fixtures qualify grammar and structural profiles, not alternate spellings as
canonical codec encodings. Existing semantic/canonical codec regressions remain.

LOW maintainability: source/operation/manifest/adoption cardinalities and encoded
path/current bounds reuse activation constants; ID/digest sizes are shared with
identity validation. Schema-key/type and necessary-field mirrors remain manual
and explicitly require review with model changes. `UPSTREAM.sha256`,
`observer.patch`, `vendor.py` and the fork README document reproducible provenance
and upgrade responsibilities. MIT license and original author attributions remain.

## Operational preservation and test meaning

No production locking, ownership, recovery, selection, authorization or digest
framing logic is changed. New D8.1 tests exercise a hostile generation with the
correct exact-byte digest. New D8.2 tests reject hostile persisted generation
bytes before plan publication/current selection, preserve the underlying parser
error and successfully activate after restoring valid bytes.

Existing B1.1 tests exercise H1 early unknown-subtree rejection, H2 exact
8 MiB/8 MiB+1/16 MiB documents, canonicality/digest reconstruction and H3 aliases
retained before factory calls, including rvalues and nested heap buffers.
Authorization statistics count events, ordinary-new probes count requested bytes:
neither establishes a live-memory/RSS limit. Source-derived budgets deliberately
preserve historical document cardinalities. Container-context memory is O(C);
ASTs, byte snapshots, hex buffers and model copies can coexist. No global linear
time or hardware-safe memory ceiling is asserted.

The preliminary run in `qualification/m2.5-d8-b1-toml-20261015-1/` is superseded:
its snapshot predates preserving upstream diagnostic literals. It is not final
qualification evidence. The final transform changes only identifier/header-name
tokens and leaves comments, string/character/raw literals unchanged. Malformed
differential fixtures compare original diagnostic text as well as rejection,
and the legacy store test compares its malformed diagnostic to the original
upstream wrapper.

## Remaining limits

The qualification targets GNU C++ 16.2.1 on the recorded Gentoo/Linux MSI, C++20,
default upstream/fork macro configuration, Debug `-g` and Release `-O3 -DNDEBUG`;
assert-based historical tests retain `-UNDEBUG`. It does not qualify arbitrary
compiler/platform/macro combinations, physical scanner/migration prerequisites,
power loss, a global RSS ceiling or universal ODR absence. Two parser namespaces
can increase code size/compile cost; the complete vendored tree is approximately
844 KiB including provenance/tooling. Manual schema mirrors remain a maintenance
obligation, with the all-profile corpus as a regression matrix.

The new original-parser diagnostic test emits one benign `nodiscard` compiler
warning because it deliberately invokes a parse expected to throw and ignores
its return value. No production warning was observed. This does not suppress
any runtime assertion or error check. Release also reports the pre-existing
ignored `write()` result at `tests/core_foundation_test.cpp:135`; that file is
unchanged by stabilization.
